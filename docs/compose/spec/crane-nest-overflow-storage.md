# 规格说明：仙鹤云巢暂存机制与纳戒满格资产保护 (crane-nest-overflow-storage)

## 1. 痛点问题 (Problem)
- **资产丢失隐患**：当百宝纳戒格位达到上限（陆拾肆格 / 64）时，若仙鹤探路归巢强制入库，要么突破格位上限使容量设定形同虚设，要么直接丢弃机缘仙物，极大挫败道友修仙体验；
- **缺乏暂存与待领交互**：当空间不足时，需有一种符合东方仙侠世界观的“灵禽护宝暂存”机制，确保道友付出灵石与时间换来的稀世机缘万无一失。

## 2. 总体设计方案 (Design)
1. **纳戒容量标准 (Capacity Bound)**：
   - 设定百宝纳戒标准容量为 `MAX_BAG_SLOTS = 64`（陆拾肆格）；
   - 前端与后端统一以 `len(char.items) >= 64` 判定为纳戒满格。

2. **仙鹤云巢暂存流转机制 (Crane Nest Overflow Buffer)**：
   - **归巢判定**：
     - 若纳戒未满 (`< 64`)：正常落账纳戒首格，弹窗提示仙物已入纳戒，提供【前往百宝纳戒查验】；
     - 若纳戒已满 (`>= 64`)：机缘物品**不进入纳戒**，转为暂存在洞府仙鹤云巢宝囊中（`crane_pending_item`）；
   - **水墨捷报弹窗表现**：
     - 弹窗提示：“百宝纳戒乾坤已满（64/64），青羽仙鹤已将【机缘仙物】稳妥衔回，暂留于洞府灵兽宝囊中，请道友腾挪空间后领取！”；
     - 提供【前往纳戒清理】与【暂留云巢】按钮；
   - **洞府设施卡片动态状态**：
     - 当仙鹤有未领机缘时，设施卡片状态由【栖息静养】动态变为【衔宝归巢 · 待取机缘】（金色流光）；
     - 卡片操作按钮变为【领取机缘】；
     - 点击【领取机缘】：若纳戒依然满格，提示“纳戒乾坤已满，请先前往纳戒移出或回售旧物”；若已腾出空位，成功将机缘存入百宝纳戒，仙鹤恢复【栖息待命】；
   - **前置防冲突**：
     - 若仙鹤云巢中尚有未领取的仙物，禁止再次派遣仙鹤，提示“灵鹤宝囊中尚有机缘仙物未取，请先领取后再行敕令启程！”。

3. **双轨数据契约与持久化**：
   - `Character` 模型新增 `crane_pending_item: Optional[dict] = None` 并参与持久化；
   - `server/world.py`：指令 `/灵鹤 领取`（或在已有 pending 且纳戒有空时取回）；指令 `/灵鹤 [秘境]` 时若已有 pending 或满格时做合理流转；
   - `web/workbench.js`：离线 Demo 与在线 Live 状态机完全对齐。

## 3. 不在本次范围 (Out of Scope)
