# F13 纪元天象主题 Spec

> 状态：已实现，评审整改完成。总纲：`docs/compose/spec/feature-completion.md` F13。
> 基线：main 0e01c88（F01–F12 已合并），全量 450 passed。

## 一、需求细化（requirement-evaluator 五步）

### 1. 解构本质
- 表层需求：每个 84 天纪元有一个「天象主题」，对全服施加一项小幅全局修正，
  开季播报、全季可见（命盘/世情），换季轮换。
- 本质诉求：让纪元不只是倒计时——玩家在整个纪元内能感知「这一世的规则微调」，
  形成跨纪元的策略差异（如灵雨纪元多闭关、金风纪元物价整体偏高），
  且修正必须可预期、可查询、跨进程一致，绝不能变成随机运行态噪声。
- 验收标准：见 §四。

### 2. 可行性评估
- 纪元编号已有单点：`core/season.py::season_info()`（epoch 文件 + SEASON_DAYS=84），
  返回 `season_number`。主题做成 `season_number` 的纯函数即可跨进程一致、零存储推导。
- 三个候选修正通道均有既有单点：
  - 闭关灵气：`core/clock.py::WorldClock.settle_meditation` 的 raw_gain 连乘链
    （density × qi × art × slot × cave × newbie × pill），末端加一环与 F02/F06 先例同构。
  - 事件权重：`core/events.py::EventEngine.pick_type` 单点读 `config.EVENT_WEIGHTS`。
  - 坊市价格：`core/market.py::MarketEngine._price_for_region` 是价格公式唯一实现点
    （F03），F09 版图折扣在成交点对市价再乘 (1−5%)，位序天然在主题之后。
- 性能：主题推导是 O(1) 查表；价格/结算路径每次多一次 season_info 文件读
  （既有 qi/season 调用已有同量级开销），可接受。

### 3. 不足与盲区
- **旧测试/旧行为污染风险**：修正若在「当前纪元」即生效，既有断言精确价格/修为的
  测试会随真实日期漂移。处置：轮转表刻意令**第 1 纪元 = 静默纪元（中性）**，
  本纪元全部旧行为逐值不变；后续纪元的修正是功能预期行为而非回归。
- **价格通道的时间锚**：`market_price` 只有 `day`（日期串）参数、无时间戳。
  处置：主题价系数按「该日期正午所属纪元」推导（day 为 None 时用今天），
  与 F03 每日波动同为日期锚定、全服一致。
- **播报重复**：纪元切换后多个玩家查询不能重复刷世情。
  处置：world_state 键 `season_theme_announced` 存已播报的最大纪元号，
  惰性触发时仅当当前纪元号大于已存值才播报。落账取舍（评审建议 1）：
  **先写标记、后发播报——宁漏勿重**：标记写成功才发消息，避免存储故障或
  双进程并发首查时重复刷屏；极端情况下（标记已写而消息落库失败）该纪元
  漏播一次，属表象损失，不伤数值，且 /天象 面板随时可查。
- **买卖套利**：价格主题若只涨买价会与回收价错位。处置：主题系数作用于
  `_price_for_region` 单点，买卖同源同系数，回收率（MARKET_SELL_BACK_RATE）不变，
  不产生新套利通道（与 F09 折扣只作用于买入成交点相区别）。
- **事件权重归一化**：权重是相对值，单类 ×1.25 只改相对占比，不改触发概率
  EVENT_TRIGGER_CHANCE，避免双重放大。

### 4. 举一反三
- 横向：F02 心法/F06 洞府已确立「连乘链末端加一环、未启用恒 1.0」的全域修正范式，
  本项沿用，不新造机制。
- 纵向：主题池是模块常量表，后续加主题只加表项 + 一条通道分支；
  轮转表长度即周期，调池不影响已过纪元的推导稳定性（同一 season_number 恒同主题，
  前提是表项只增不改序——在常量注释中写明此约束）。
- 涟漪：settle_meditation / market_price / pick_type 均为高频路径，
  接入全部用 try/except 回退中性值，主题模块异常绝不阻断结算/交易/事件；
  `theme_for_season` 返回轮转表项的浅拷贝，防止调用方误写污染全进程主题表
  （评审建议 2）。

### 5. 完善方案（真正需求）
见 §二行为契约。备选方案对比：
- 方案 A（采用）：纯函数轮转表推导，零落库（播报标记除外）。
- 方案 B（否决）：开季时随机抽取并落库——跨进程需读库、测试不可复现、
  与「规则可预期」诉求相悖。

## 二、行为契约

### 主题池与轮换（常量 `SEASON_THEME_ROTATION`，core/season_theme.py）
主题由纪元编号纯函数推导：`theme = ROTATION[season_number % 6]`，
六主题互不相同 ⇒ 相邻纪元主题必不同；同纪元任意进程/玩家推导结果一致。

| season_no % 6 | 主题 | 通道 | 修正（唯一一项） |
|---|---|---|---|
| 0 | 血月纪元 | 事件权重 | crisis 权重 ×1.25（35 → 43.75） |
| 1 | 静默纪元 | 无 | 无修正（三通道全中性） |
| 2 | 灵雨纪元 | 闭关灵气 | settle_meditation 修为产出 ×1.05 |
| 3 | 赤霞纪元 | 事件权重 | fortune 权重 ×1.25（45 → 56.25） |
| 4 | 金风纪元 | 坊市价格 | 市价 ×1.05（买卖同源） |
| 5 | 寒潮纪元 | 闭关灵气 | settle_meditation 修为产出 ×0.95 |

幅度封顶：单项修正倍率钳制在 [0.95, 1.05]（灵气/价格）；事件权重单类 ×1.25
（仅相对占比，幅度以权重常量 `SEASON_THEME_EVENT_WEIGHT_MULT=1.25` 定死）。
未被当前主题选中的通道恒为中性（倍率 1.0 / 权重原表），主题模块整体异常时
回退中性——关掉主题即旧行为。

### 生效接入（全部单点）
1. 灵气：`settle_meditation` 连乘链末端（pill_mult 之后）乘 `meditation_mult(settle 时刻)`。
2. 价格：`MarketEngine._price_for_region` 在区域系数之后乘 `price_mult(该 day 所属纪元)`；
   与 F09 折扣位序：F03 区域价 → F13 主题价 →（成交点）F09 主导折扣。
3. 事件：`EventEngine.pick_type` 的权重表改经 `event_weights()` 读取（返回修正副本，
   不改 config 原表）。

### 可见性
- `/天象`（别名 `/omen`）：显示当前纪元号、主题名、修正说明、剩余天数；双端一致，
  查询类，闭关放行（对齐 /版图、/飞升榜先例：server 闭关白名单 + CLI 闭关豁免名单）。
- 命盘/status：`_status_dict` 纯加法字段 `season_theme = {name, key, effect, season_number}`；
  网页命盘卡展示主题名一行（`stTheme`），世情卡加「天象」按钮（data-cmd="/天象"）。
- 双端帮助行同步登记 /天象。

### 开季播报（惰性、幂等）
- 触发点仅三处查询：server `/天象`、server `/纪元`、CLI `/天象`——纪元切换后
  首次被查询时，经既有世情通道（WorldChannel，kind="season_theme"，level="epic"）
  播报本纪元天象；无新线程、无 tick 挂载。
- 幂等：world_state 键 `season_theme_announced` 存已播报的最大纪元号；
  当前纪元号 ≤ 已存值不重播。落账顺序为先写标记后发播报（宁漏勿重，见 §一.3）。
- 标记值损坏（非数值）时按 0 处理、自愈重写，不抛错给查询路径。

### AI 边界
主题推导、修正、播报文案 100% 规则与本地模板，零新增 AI 调用。

## 三、明确不做（Out of Scope）
- 主题对寿元、突破率、战斗数值的直接修正（只动灵气/价格/事件权重三通道）。
- 玩家/宗门对主题的选择、投票或干预；主题的叠加（每纪元恒恰一项修正）。
- 播报的历史补播、天象专属面板页（网页仅命盘一行 + 按钮）。
- 纪元长度（84 天）与大劫结算逻辑的任何变更。

## 四、验收标准
- [x] 推导：同纪元编号多次/跨进程推导同一主题；相邻纪元主题不同；
      第 1 纪元为静默纪元（测试钉死）。
- [x] 灵气通道：真实 settle_meditation 路径上，灵雨纪元收益恰 ×1.05、
      寒潮恰 ×0.95（同种子同口径比值断言）。
- [x] 价格通道：真实 market_price 路径上，金风纪元市价恰 ×1.05（基准区 300→315）；
      回收价同源同步；与 F09 折扣叠加位序数值断言（315→299）。
- [x] 事件通道：赤霞 fortune 权重 56.25、血月 crisis 权重 43.75，其余通道中性；
      event_weights 返回副本不污染 config 原表。
- [x] 中性路径：静默纪元三通道倍率 1.0、权重与价格逐值等于旧公式；
      主题模块异常时三通道回退旧行为（故障注入测试）。
- [x] 播报：同纪元多次惰性触发恰播报一次；换季再播；标记损坏自愈。
- [x] 双端：server handle /天象、/omen 通路 + status.season_theme 透出 +
      闭关白名单放行；CLI 处理器/豁免/帮助行源码对齐。
- [x] 全量回归 0 失败（基线 450 + 本项新增）。
