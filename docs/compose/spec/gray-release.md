## 阶段一 · 真正需求（五步推演收敛）

### 1. 解构本质
- **表层需求**：继续开发，直到「可灰度版本」停下。
- **本质诉求**：让一批**真实的外部玩家**（非作者本人）在**作者不陪跑救火**的前提下，
  完整玩通一世循环，并能收集真实反馈。灰度 ≠ 功能堆满，灰度 = **可交付、可诊断、可回滚**。
- **核心不变（硬约束）**：寿元硬通货（1 游戏年 = 现实 1 天）、规则引擎裁决数值、
  LLM 只做叙事 / NPC 言行 / 事件提案、一世循环 + 84 天赛季、文字 LAN 单进程形态。

### 2. 可行性评估
- 现状已具备：核心循环闭环、账号/会话、SQLite 持久化（含 world_state / npc_agendas / npc_minds）、
  `/health` 雏形、61 个测试文件（240 用例）、局域网网页端主界面。
- 技术栈无阻塞：纯 Python + 静态网页，补齐均为小步增量，不需架构迁移。

### 3. 不足与盲区（灰度阻塞项，均为实测）
| # | 阻塞项 | 证据 |
|---|---|---|
| G1 | 测试基线不稳：`test_events_ai` 危机用例随机失败约 50% | 危机事件池 4 条中 2 条只改道心/业力，不改灵石/寿元，用例断言过窄；灰度前 CI 结论不可信 |
| G2 | AI 通道单点且不可见：`/health` 不报 AI 状态 | backlog 体验债 A「AI 通道 401 时体验全塌」；房主无法自检 |
| G3 | 配置无样例：新房主不知道要配什么 | 无 `.env.example`；README 只有片段 |
| G4 | 网页端看不见行囊/已穿戴装备 | `_status_dict` 未下发 `inventory/equipped`；玩家只能靠 `/道身` 文本，灰度玩家门槛高 |
| G5 | 天道不可感知：血煞/大限在网页命盘无标识 | 蓝图 C3 未落地（网页侧）；status 已有 sin / rem_years 数据，纯前端可补 |
| G6 | 无版本标识与灰度运行依据 | 无 VERSION / CHANGELOG / 运行手册；出问题无法回滚到已知版本、无备份口径 |

### 4. 举一反三
- G2 与 G4 同源于「状态不可见」：服务端已有数据，缺下发与呈现 — 本批只补呈现，不动规则。
- G1 的根因模式（随机池 × 窄断言）可能存在于其他事件类用例：全量连跑 3 遍作为灰度门禁，暴露同类问题。
- 灰度房主即运维：手册必须覆盖备份存档、重置世界、AI 故障判定，否则灰度反馈全是环境问题。

### 5. 完善方案（批次划分）
- **批次 A · 稳定性**：A1 修 flaky 用例（只改测试断言为全属性快照比对，不改游戏规则）；
  A2 补 `.env.example`；A3 `/health` 增强（version / ai_available / ai_required / allow_local_ai / 在线人数）。
- **批次 B · 体验**：B1 `_status_dict` 下发 `inventory / equipped / arrays`（纯新增字段，向后兼容）；
  B2 网页新增「行囊」卡（物品列表、已穿戴标识、点击穿戴/卸下/服用走既有指令）；
  B3 命盘加「血煞缠身」「大限将至」标识（阈值与规则侧血煞口径对齐，只做呈现）。
- **批次 C · 交付**：C1 版本号 `0.1.0-gray.1`（`config.py` 常量 + `/health` 回显）；
  C2 `CHANGELOG.md`；C3 `docs/gray-runbook.md` 灰度运行手册；C4 全量回归 ×3 + LAN 冒烟实测；
  C5 合并 main、打 tag `v0.1.0-gray.1`、推送。

### 明确不做（Out of Scope）
- 不加新玩法系统（灵宠 / 心法槽位 / 跑商等加厚清单留待灰度反馈后排期）。
- 不动核心数值与规则语义；不做公网架构、付费、Steam、多服。
- 不改存档结构（world_state 等表已够用）；`_status_dict` 只加字段不改旧字段。

## 验收标准（灰度门禁，须全部有证据）
1. 全量 pytest 连续 3 遍 **0 失败**。
2. 全新环境按 README 步骤可起服；`/health` 返回 version 与 AI 状态字段。
3. 无 AI（`ALLOW_LOCAL_AI=1` 且无 Key）下 LAN 冒烟通过：注册/入世/闭关/出关/坊市购买可用。
4. 服务重启后角色与世界态存续（既有 persist 用例 + 冒烟复核）。
5. 网页端不输入指令即可看到行囊物品与已穿戴装备；命盘可见血煞/大限标识（构造状态验证）。
6. 仓库含 VERSION 标识、CHANGELOG、灰度运行手册；tag `v0.1.0-gray.1` 已推送。
