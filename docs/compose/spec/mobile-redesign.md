## 阶段一 · 五步推演（简写，方法见 requirement-evaluator）

### 1. 本质解构

- **表层需求**：Martinez 看完移动版觉得不好看，让设计师重做。
- **本质诉求**：移动版功能已齐（mobile-web M-1～M-20 通过），但**视觉上不像一款修仙游戏**——像套了绿头的通用表单：全站一个衬线字体、卡片无层级、导航用文本符号、门庭无仪式感、暗色主题没设计过。玩家第一眼得不到「这是天道因果录」的确认，后续功能再全也留不住人。真人试玩在即（仍 0 样本），第一印象就是留存。
- **伪需求排除**：换一套高饱和配色 / 加大字号 / 加背景图都不是解法——问题在**系统缺失**（无 token、无字阶、无组件规范、无层级），不在某个颜色不好看。只调颜色会重蹈 v0.2.4「修补丁」的覆辙。
- **验收标准**：见 §验收 R-1～R-24；核心是「同一功能、同一 DOM 钩子下，逐屏截图可被一眼识别为修仙游戏；对比度、触控、667 矮屏、暗色主题全部达标；功能零回归」。

### 2. 可行性评估

- **技术可行性：高**。纯 `mobile.html` / `mobile.css` 改动 + `mobile.js` 渲染字符串的结构调整；无新端点、无 `core` 改动、无数据模型改动；图标用内联 SVG（无新文件、无 app.py 改动）；动效只用 CSS transition/animation。
- **性能/成本**：CSS 预算内（D7：≤20KB）；无新增网络请求（首屏请求数不变：`mobile.html` + `mobile.css` + `mobile.js`）；无新增轮询；`backdrop-filter` 在手机上慎用（见 D4-⑤），避免低端机卡顿。
- **唯一中风险**：`mobile.js` 渲染字符串改动面大（命盘/行囊/世界/操作四区），改结构时易误删 `data-*` 钩子或改错命令文本——用 R-18 的钩子清单 + 全量回归对冲（R-20），不用「少改点」对冲（少改就达不到设计目标）。

### 3. 不足与盲区

1. **667 矮屏**：固定坞区（导航 56 + 命令坞 ~60 + 快捷条 ~56 ≈ 172px）占 844 屏的 20%、667 屏的 26%；门庭在 667 下已超高（见 §1 gate-667）。设计必须给坞区定总高预算，给门庭定纵向预算（D4-④、D5-①）。
2. **键盘态**：`body.kb-open` 隐藏导航、命令坞沉底——重做坞区结构时必须保留这一行为，Toast 与建议框（`#suggest`）在键盘态的位置要重新核对（R-16）。
3. **暗色主题是二等公民**：现状暗色只有零散覆盖规则（`.card`、`.feed-line`、输入框等），大量文字色（`.muted`、`.kv .k`、`.tip`、`.section-title`）没有暗色值，直接继承浅色值导致对比度崩坏（C3）。本轮暗色必须与浅色**同表设计**（D2 token 表双列），逐条验收。
4. **iOS Safari**：输入框 16px 是硬指标（低于 16px 聚焦自动放大整页）；`100dvh` 与 `env(safe-area-inset-bottom)` 已在用，重做后仍须保留；内联 SVG 在 iOS 无兼容问题。
5. **横屏 844×390**：mobile-web M-11 只要求无横向滚动、无遮挡；本轮不做横屏专属布局，但坞区总高预算须保证横屏下内容区仍 ≥120px 可见（R-15）。
6. **空态是设计的一部分**：动态/行囊/同场修士三处空态目前都是裸 muted 文字，大面积留白（bag 截图尤甚）。空态必须有正式设计（D5 各屏），不是「有数据就好看」。
7. **文案是设计**：门庭页脚「手机版 · 根地址自动进入 / 默认阵枢：mn.20230803.xyz:8765」是技术说明文案，放在游戏门庭里破仪式感；重做须把技术信息收进一行小字、把仪式感还给门庭（D5-①），但**默认阵枢地址本身不得改、不得藏到找不到的地方**（R-7 功能回归项覆盖）。

### 4. 举一反三

- **横向**：桌面端 `workbench.css` 已有玉面板/金边/印章等组件语言，移动版不是从零发明，而是把桌面语言**收敛成 token + 降维到单列**；桌面后续若做视觉升级，可直接复用本 Spec 的 token 表（反向收益，不在本轮做）。
- **纵向**：token 表与组件规范一旦确立，后续新增移动分区（如坊市完整面板、宗门面板）直接套用，不再每屏各写一套颜色；`data-theme` 双列 token 使「昼夜天象」从临时覆盖升级为正式主题。
- **涟漪面**：`web/mobile.html`（结构/图标）、`web/mobile.css`（全部视觉）、`web/mobile.js`（四区渲染字符串 + ops 芯片列表去重）；`tests/test_qa2_frontend_contract.py`（契约断言须覆盖新结构，见 R-19）；截图验收工具沿用 mobile-web M-19 的 shot 脚本（只换断言，不换工具）。**不触及**：`server/app.py`（无新静态文件）、桌面三件套、`core/`、接口、存档、轮询节律、分流逻辑。

### 5. 完善方案

- **推荐路径**：本 Spec 的设计语言（D1～D3）+ 逐屏说明（D5）+ 组件规范（D4）→ 前端岗按 D6 任务清单实现 → 截图 + 量测验收（R-1～R-24）→ 独立评审审 diff（只审 Spec 符合性与钩子完整性）→ 回归。
- **备选方案对比**：
  - A 把移动版默认翻成深墨蓝（呼应任务书字面）：视觉冲击最强，但与实际桌面页断裂、户外可读性下降、暗色 token 尚未验证——**否决作默认，保留为夜天象的正式设计**（D-0）。
  - B 只调颜色不动结构：成本最低，但层级、坞区、空态、图标四大问题一个都解决不了——**否决**。
  - C 引入图标字体或背景图：图标字体是新外部依赖（禁）；背景图是新静态文件请求（须改 app.py 白名单两处，扩大改动面）——**否决，图标一律内联 SVG，氛围一律纯 CSS 渐变**。

## Problem

1. **没有设计系统**：`mobile.css` 203 行、25 个散落色值，无 token、无变量；同一语义多处各写各的（如边框色 `#e2d7be` / `#c5e2d5` / `#eee8d8` 混用，圆角 8/10/12/16px 四档并存，字阶 12/13/14/15/17/24px 无规律）。改一处不敢动全身，加一屏就新增一套。
2. **层级塌陷**：命盘 17 行 kv 等权排列（D5-③详述）；世界页三按钮等权（切磋与传音同级）；操作页灰色小标题 + 两列等权按钮；动态流四种 kind 只靠 4px 左边框区分。用户扫一眼不知道先看哪、哪个是主操作。
3. **氛围缺失**：门庭是绿渐变矩形 + 圆圈「道」字，无夜空、无灵气、无纵深；全站无一处金色细线、印章、眉题等桌面已有的东方意象；底部导航是五个文本符号（☰ ◆ ▣ ◎ ✦），☰ 还是汉堡菜单的隐喻，与「动态」无关。
4. **固定坞区过重且互相打架**：导航/命令坞/快捷条三条固定带、三种底色（`#10332c` / `#fdfbf7` / `#f7f4ec`），占屏 172px；Toast 压住快捷条（C4）；快捷条与操作页「常用命令」芯片**内容完全重复**（同一批 8 个命令出现两次）。
5. **暗色主题未设计**：辅助文字对比度 2.88:1（C3），卡片与背景几乎同亮度（`#10332c` 卡片 on `#0b1d16` 背景），边框 `#1a4a40` 在暗底上近乎隐形。
6. **矮屏与空态失守**：390×667 门庭底部「桌面版」入口在首屏外；行囊/动态空态是大面积空白 + 一行灰字；390×667 动态首屏内容区被坞区挤到约 300px。

## Design

### D-0 · 家族裁定（见 §0-C2，本 Spec 最高优先级决策）

- 移动版与**实际在跑的桌面页**（`index.html` + `workbench.css`，浅色宣纸 + 翡翠 + 描金）同族，不与已弃用的 `style.css` 深色页同族。
- 深墨蓝（`#0a0d12` 系）是**夜天象**的正式语言，不是被遗忘的默认值；两天象共用 token 名，金色贯穿两档。
- 拒绝「另起一套」：色值全部取自桌面 Tailwind 色板与 `style.css :root`，不发明新主色；字体角色沿用桌面分工（sans 正文/UI、serif 标题/印章）。

### D1 · 设计语言总述（一句话）

**「宣纸为底、翡翠为骨、描金为线」**：浅色宣纸底上，翡翠承担结构与主操作，描金只出现在细线、眉题、选中态与数字上，克制使用；夜天象时底色翻转为深墨蓝，翡翠退为点缀，描金升为主角。

- 质感来源只许三样：纯色分层、1px 金线、CSS 径向光晕（门庭与顶栏）；**不许**纹理图片、毛玻璃大面积使用（`backdrop-filter` 只许门庭卡片在支持的设备上做装饰性增强，且须有纯色回落）、阴影只许两档（卡片浅影、主按钮金影）。
- 每一屏必须一眼回答三个问题：我是谁（顶栏）、我在哪（分区标题 + 眉题）、下一步干什么（主操作）。

## 真正需求条目（收敛结论，开发与验收的唯一依据）

1. **问题**：移动版功能已齐但视觉不成立——无设计系统、层级塌陷、氛围缺失、坞区打架、暗色未设计、矮屏与空态失守（§1 逐屏审计为准，基线截图 m19 系列）。
2. **行为契约**：同一功能、同一 DOM 钩子、同一接口下重做视觉与体验：设计语言为桌面浅色翡翠宣纸家族的精致化表达，深墨蓝为夜天象正式语言（D-0）；token 双列、字阶、间距/圆角、组件规范、动效原则见 D2～D4；逐屏说明见 D5；任务清单见 D6。
3. **边界**：只动 `web/mobile.html` / `web/mobile.css`，`mobile.js` 只做最小结构配合；`server/app.py`、桌面文件、`core/` 一律不动；无外部字体/CDN、无新图片请求、无新静态文件（默认）；CSS ≤20KB。
4. **验收标准**：R-1～R-24，含截图对照、对比度实算、触控量测、667/横屏/键盘态、钩子冻结、契约测试、全量回归、体积预算。
5. **不做范围**：见 Out of Scope 1～8。
