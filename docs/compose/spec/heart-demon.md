# F16 心魔长期状态机收尾 — Spec

## 一、问题（五步细化结论）

- **表层需求**：把心魔从一次性问答升级为长期状态：心魔种（血煞反噬/杀业累积）→
  蛰伏/滋长阶段 → 闭关或突破时发作 → 镇压（丹药/道心）或入魔风险；全程规则数值，
  AI 只演心魔之言。
- **本质诉求**：现有心魔只有大境界突破前的一次性问答（`core/heart_demon.py`），与玩家
  平日的杀业/血煞积累毫无关系——杀人如麻与清心寡欲者在问心时面对同一套流程，
  业力账本（sin/blood_mark）缺少一个把「平日因」结成「临关果」的长期载体。
  本项在既有问答之上叠加一条纯规则的长期状态机，不推翻既有判定。
- **现状盘点（实测）**：
  1. 既有问答：大境界突破（sub_tier==3）时 server `_breakthrough` / CLI 突破路径调用
     `HeartDemonEngine.start`（AI 生成叙事+选项）→ 玩家选择 → `resolve`（AI 裁定
     outcome ∈ pass/wound/heart_hit/dao_crack/fail/death → `EventEngine.apply_effects`
     落账 + tribulation_mod ±0.15）；death 门：AI 判 death 且**有效道心**（本体 +
     F10 炼神加值，`BodySoulEngine.effective_dao_heart`）≤20 才真死。角色上**无任何
     心魔状态字段**。
  2. 血煞：`KarmaLedger.add_sin` 每次加业力同时把 `blood_mark_until` 刷新 +3 游戏年；
     「血煞反噬」是 crisis 本地事件模板（effects: sin=sin//10、dao_heart −5），经
     `EventEngine.fire` → `apply_effects` 落账——这是血煞反噬的唯一落账点。
  3. 杀业：`sin_value` 由斗法击杀/偷袭/事件链/诺言违约等十余处经 `add_sin` 累积，
     **无单一落账点**（KarmaLedger 无角色反引用，无法在 add_sin 内挂钩子）。
  4. 道心：`karma.dao_heart` 本体 0~100；有效道心 = min(100, 本体 + 炼神加值≤20)，
     突破 heart_penalty 与心魔 death 门均读有效道心（F10 先例）。
  5. 丹药目录无清心/静心类丹药；`百年灵芝`（material，价 55，desc「温养道基的药材」，
     探险掉落/灵田产出/坊市有售，F10 炼神已用）最合「温养道基、压制魔念」之义。
  6. 闭关结算单点：`WorldClock.settle_meditation`（core/clock.py），server 与 CLI
     全部出关路径都经它，成功路径只有一个 return。

## 二、行为契约

### 2.1 状态模型（角色新字段，带默认值，旧档自动补 0）
- `demon_seed: float = 0.0` —— 魔念值（心魔种的量化）。0 = 无种。
- `demon_anchor_at: float = 0.0` —— 惰性结算锚点时间戳；0 = 从未同步（首同步只建基线）。
- `demon_sin_seen: int = 0` —— 上次同步时见过的 sin_value（杀业增量推导基线）。
- `demon_calm_at: float = 0.0` —— 上次「静坐镇魔」时间戳（冷却用）。
- **阶段不落库、纯推导**：`stage(seed)`：seed≤0 → 0 无种；<40 → 1 蛰伏；
  <90 → 2 滋长；≥90 → 3 临发。阶段名：无种/蛰伏/滋长/临发。

### 2.2 魔念来源（只认既有事实，惰性推导优先）
魔念有效值 = 落库 demon_seed + 两路惰性增量（`effective_seed(c, now)` 纯读推导；
`sync(c, now)` 在动作/发作/面板点把增量落库并推进锚点与 sin 基线）：
1. **杀业增量**：Δsin = max(0, sin_value − demon_sin_seen)，魔念 += Δsin × 0.5。
2. **血煞缠身时长**：锚点以来血煞覆盖秒数（由 blood_mark_until 与锚点/now 区间
   交集推导），魔念 += 覆盖天数 × 2.0。
两路增量都乘**道心压制系数**（按有效道心）：<60 → ×1.0；60–84 → ×0.5；≥85 → ×0.25。
- **首同步建基线**：demon_anchor_at==0 时只写锚点与 sin 基线、不追溯历史杀业/血煞
  （存量玩家不因旧账被追溯播种——与「无种老玩家行为不变」一致；上线后新发生的
  事实才计入）。
3. **血煞反噬播种（事件钩子）**：`EventEngine.fire` 落账后若事件 title==「血煞反噬」，
   以概率 p = 0.60 − 有效道心 × 0.003（道心 0 → 0.60，100 → 0.30）播种：
   魔念 += 25（无种者直接入蛰伏）。钩子 try/except 包裹，失败不影响事件本身。

### 2.3 发作（阶段 ≥2 才可能；无种/蛰伏永不发作，旧行为钉死）
1. **突破问心（复用既有交互问答，零新判定）**：`HeartDemonEngine.start` 时若
   stage≥2，按概率掷「发作」：滋长 0.35 / 临发 0.65。命中则该 session 标记
   `eruption=True`（HeartDemonSession 新增带默认字段，旧 session 恒 False）。
   `resolve` 既有结算完成后追加阶段后果（新引擎 `apply_eruption_outcome`）：
   - outcome=pass → 魔念降至当前阶段下限 −1（回落一阶），附言「心魔退却」；
   - outcome=wound/heart_hit → 魔念 +5；
   - outcome=dao_crack/fail → 阶段<3 时魔念 +15；阶段==3 时触发**入魔档**（见 2.5）；
   - outcome=death → 既有死亡口径已处理，不再追加。
2. **闭关结算（规则内斗判定）**：`settle_meditation` 成功且未坐化时，stage≥2 者
   按概率掷发作：滋长 0.25 / 临发 0.50。闭关结算是回顾性结算、无法交互问答，
   故以**规则内斗**裁定（与既有问答同一 outcome 词汇与效果 caps，不是第二套问答）：
   胜率 p = clamp(0.20, 0.90, 0.45 + (有效道心−50)×0.006 − (stage−2)×0.12)；
   掷骰 r：r<p → pass（魔念回落一阶、道心 +2 钳 100）；r<p+0.35 → wound
   （道心 −8、魔念 +5）；其余 → fail 档（道心 −15、魔念 +15；stage==3 时入魔档）。
   结果以 `demon_eruption` 键并入结算 dict（加法键），server 出关文案与 CLI
   结算渲染各追加一行心魔叙事（本地模板，心魔之言风格）。
- **防刷/防规避**：发作概率只由阶段决定、阶段只由真实杀业/血煞/反噬事实推升，
  玩家无法通过反复开关问心刷低概率（start 的发作掷骰每次突破至多一次，且问心
  本身必须走完 resolve 才推进突破）；唯一正当规避 = 镇魔降种（设计内路径）。
  镇魔与发作互斥于同一结算：闭关结算先出关结算本体、后掷发作，不可先镇后结。

### 2.4 镇压（/镇魔，双端一致）
- `/镇魔`：面板——阶段、魔念值、来源提示（当前业力/血煞状态）、两条镇压路径与成本、
  发作风险说明。面板打开即 sync（惰性落库，与 F07 面板 settle 先例一致）。
- `/镇魔 服丹`（主路径）：消耗 百年灵芝 ×1 + 灵石 30 → 魔念 −35。资源不足零扣费
  拒绝；魔念归零即除种（stage 回 0）。
- `/镇魔 静坐`（道心硬抗）：要求有效道心 ≥50；冷却 20 现实小时（demon_calm_at）；
  无物品/灵石成本 → 魔念 −20。冷却中/道心不足明确拒绝、零变更。
- 指令不进闭关白名单（面板与行动一并锁门，对齐 F02/F06/F10 防临场刷口径）；
  死亡由引擎双查拒绝（status DEAD 或寿元到期）。

### 2.5 入魔档（既有最重惩罚的加重档，非新状态分支）
触发：临发（stage 3）发作判定落 fail 档（突破问答 dao_crack/fail 或闭关内斗 fail）。
后果（走既有口径）：道心 −20（= EVENT_EFFECT_CAPS dao_heart 单次幅度上限）、
业力 +40（= caps sin 上限，经 add_sin 落账、自带血煞刷新）、魔念置于临发下限 90
（魔种深种不清零）、jianghu 世情播报「心魔入魔」一条。不新造死亡外后果体系，
不直接致死（死亡仍只走既有 death 门）。

### 2.6 可见性与双端
- server + cli 同引擎四形态：/镇魔、/镇魔 服丹、/镇魔 静坐（别名 /demon）。
- `_status_dict` 纯新增 `heart_demon_state: {stage, stage_name, seed}`（seed 为
  effective 取整；纯读推导不落库，与 _status_dict 只读语义一致）。
- 网页：命盘区显示心魔阶段（app.js 读 status.heart_demon_state，无种时显示「心魔：无种」不隐藏）；
  修行卡加「镇魔」「镇魔·服丹」按钮（data-cmd 模式）。
- 死亡：新字段随角色一世存续，新角色默认 0 即闭环（与 F10 先例一致），无额外清理。

### 2.7 AI 边界
播种/阶段/发作/镇压/入魔全部规则判定，常量在新模块 `core/heart_demon_state.py`。
突破发作复用既有问答——其叙事与心魔之言本来就走既有 AI 通道（AI 只演言、不定数值，
后果由本状态机按 outcome 规则追加）。闭关内斗叙事用本地模板池，零新增 AI 调用。

## 三、边界
- 无种（seed=0）者：start 不掷发作（session.eruption 恒 False）、闭关不掷发作、
  resolve 不追加任何后果——全路径与 F16 前逐值一致（关键回归，测试钉死）。
- NPC：字段同在 Character 上，但播种钩子/发作检查点只挂玩家路径（EventEngine.fire
  对 NPC 亦可能触发反噬播种——NPC 魔念只累积、无人镇压，属可接受的世界自洽；
  发作检查点（突破问心/闭关结算）NPC 不走玩家指令路径，自然不发作、不影响玩家）。
- 魔念封顶 150（防极端值污染面板/公式）；镇压扣减不为负（钳 0）。
- sync 幂等：同 now 重复 sync 增量为 0；锚点只前进不后退（now<锚点时按锚点计）。

## 四、验收标准
1. tests/test_heart_demon_state.py 覆盖：播种两路（反噬概率门注入 rng、杀业增量
   推导含道心压制系数）、首同步建基线不追溯、阶段阈值推导与惰性推进、血煞时长路、
   无种者 start/resolve/闭关全路径旧行为不变、突破发作标记与 outcome 后果
   （pass 回落/wound +5/fail +15/临发 fail 入魔数值断言）、闭关发作概率门与内斗
   三档数值断言、镇压服丹扣费与 −35/静坐冷却与道心门/归零除种、入魔档 caps
   断言、炼神有效道心在压制系数与内斗胜率中生效、server handle 至少 1 条
   （/镇魔 全流 + status 透出 + 闭关锁门）、旧档反序列化兼容。
2. 全量回归 0 失败（基线 507 + 新增）。
3. 独立评审通过（重点：无种零变化、发作不可刷、镇压不重复扣/降）。

## 五、Out of Scope
- 心魔独立战斗场景/专属秘境；NPC 发作与 NPC 镇魔；多人助阵镇魔；
- 魔念对战力/突破率的直接修正（只经既有问答 tribulation_mod 与道心口径）；
- 新丹药入目录（百年灵芝兼任已够闭环）；心魔排行榜/称号；
- 既有问答的 AI 裁定逻辑、death 门阈值、突破概率公式——一律不动。
