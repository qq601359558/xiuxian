# F15 除凶令状态机收尾 — Spec

> 总纲：docs/compose/spec/feature-completion.md F15。
> 定位：**收尾**——把既有除凶碎片补成完整状态机；不推翻任何既有结算口径，不新造线程/AI。

## 一、需求细化（requirement-evaluator 五步）

### 1. 本质解构
- 表层需求：除凶令要有「发布 → 接令 → 追凶 → 围剿 → 结算」完整状态机，与悬赏板/委托/宗门环去重对齐。
- 本质痛点：现状 `core/hunt.py` 只有「猎手→单目标」的 KV 映射（`hunts`），没有以凶犯为中心的
  「令」实体：令的发布是隐式的（看板实时扫全服标记角色推导）、多人接同一令无共享状态、
  围剿只有战斗系数没有分账、令的消散/过期只靠猎手侧 TTL 惰性清理，凶犯洗清血煞或被他人
  击杀后猎手侧残留悬挂记录；且无「追凶」情报指令，看板直接暴露凶犯精确地点（实时定位）。
- 验收标准：见 §五。

### 2. 现状盘点（实测，2026-11-04）
| 碎片 | 现状 | 缺环 |
|---|---|---|
| 凶犯产生 | `KarmaLedger.add_sin` 沾血煞 3 游戏年；`hunt.is_marked` = 血煞中 或 业力 ≥ `SIN_THRESHOLD=80`，玩家与 NPC 同口径 | 无缺环（规则已定） |
| 发布 | 无令实体；`format_board` 实时扫描存活角色推导榜单 | **缺**：无令记录、无发布时点、无去重载体 |
| 接令 | `accept`：每猎手同时 1 个目标，`hunts[hunter_id]`，TTL 48h（`HUNT_TTL_H`）；成功触发宗门环 hunt 钩子 | **缺**：同一令接令人数无上限、无令侧登记 |
| 追凶 | 无指令；看板行直接显示凶犯精确 `@地点` | **缺**：无情报指令、无时效口径 |
| 围剿 | `announce_siege` 仅播报；`siege_multiplier` 同场 ≥2 猎手/玩家时战斗系数 1.15 | **缺**：同场协剿者无分账 |
| 结算 | `settle_kill`（combat_fate 击杀点调用）：击杀者功德 +40、业力 −20（仅限接了该目标者）；版图 hunt 钩子 +10 在此触发；反悬赏 `settle_hunter_slain`/`place_counter` 独立闭环 | **缺**：令无终态、其他接令者记录不清理、协剿者无份 |
| 悬赏板 | `core/bounty.py` 完整状态机（OPEN→CLAIMED→COMPLETED/EXPIRED/CANCELLED），玩家出资灵石 + 功德 `BOUNTY_HUNTER_MERIT`=15，`settle_on_kill` 仅 CLI 击杀路径调用 | 与除凶并行存在，口径不动 |
| 宗门环 | `sync_ring(char,"hunt")`：**接除凶令成功**即完成当日 hunt 环（贡献+8/功德+2/灵石50） | 计数口径不动 |
| F07 委托除妖环 | 探险成功计数（AdventureEngine 钩子），与直接击杀无关 | 不叠加、不动 |
| F14 不攻诺 | combat_fate 出手点 `note_attack` 事实钩子 | 不发钱、不动 |

### 3. 可行性
- 令实体存 world_state 新 KV `hunt_orders`（target_id → order dict），与既有 `hunts` KV 并存：
  `hunts` 继续做猎手侧索引（`my_target`/`siege_multiplier`/`settle_kill` 旧路径零改动语义），
  order 做令侧状态机。存档只加 KV，无新表无改表。
- 惰性推进：发布/过期/消散全部在既有访问点（看板、接令、追凶、结算）惰性判定，不新造线程。

### 4. 盲区与风险
- **一杀多领**：同一击杀既有可叠加通道——combat_fate 血煞功德 +60（任何人）、悬赏板灵石
  （玩家出资）、除凶功德 +40（接令击杀者）。均为既有口径，本项不改；F15 新增的只有
  「协剿功德」，且只发功德不发灵石，单通道封顶（见 §三对照表）。
- **悬挂令**：凶犯被未接令者击杀、或血煞到期+业力降至阈值下（洗清），令须消散并清猎手记录，
  否则猎手被死令占位（每人仅 1 令）。以惰性消散覆盖全部访问点。
- **陈旧对象**：结算时协剿者必须从仓储现读现存（F05/F14 教训），不用调用方传入的旧对象发钱。
- **直写 KV 的旧测试**：tests/test_atlas 直接写 `hunts` KV 后调 `settle_kill`（无 order），
  结算层必须容忍「有猎手记录、无令实体」并正常走旧口径（无协剿、无终态写）。

### 5. 完善方案
在 `core/hunt.py` 内增令状态机层（不拆新模块，与既有函数同文件同口径）：
`ensure_order` 惰性发布/过期/消散；`accept`/`abandon` 同步令侧登记；`track` 追凶情报；
`settle_kill` 在旧结算之后追加协剿分账与令终态。指令双端补齐 `/接令 /追凶 /弃令`
（旧名 `/接除凶 /弃除凶` 保留为别名）。

## 二、行为契约

### 状态机
```
（凶犯达标记阈值，首次被看板/接令/追凶/结算访问）→ OPEN（发布，惰性）
OPEN ──接令──→ OPEN（hunters 登记，上限 ORDER_MAX_HUNTERS）
OPEN ──接令者击杀凶犯（settle_kill）──→ SETTLED（终态：击杀者旧赏 + 同场协剿分账，清全部猎手记录）
OPEN ──令到期（issued_at + HUNT_TTL_H）──→ EXPIRED（终态：惰性，清猎手记录，无奖惩）
OPEN ──凶犯洗清（不再 is_marked）或已被他人击杀──→ DISSOLVED（终态：惰性，清猎手记录，无奖惩）
```
终态不可逆；终态后凶犯再次达阈值可重新发布新令（新 order 覆盖同 target 槽位）。
EXPIRED 可观察性（评审 S3 裁定）：_sweep_orders 推进的 EXPIRED 会落盘保留；ensure_order 在
同一调用内发现过期且凶犯仍在标记中时，先关旧令再立即重发新令，旧 EXPIRED 被新令覆盖——
这是「看板即发布点」的预期行为，验收 5 以 sweep 路径与结算点（settle 时过期→EXPIRED 不发
协剿）为准。
结算点复核（QA-02 裁定，2026-11-04 修订原「结算点不做洗清判定」口径）：存在 OPEN 令时，
settle_kill 在发放任何除凶奖励前先复核目标状态——过期优先走 EXPIRED（与 _sweep_orders
同序）；未过期但目标已洗清（不再 `is_marked`）→ DISSOLVED。结算点**只看 is_marked、不看
status**：combat_fate 先置 DEAD 再调 settle_kill，DEAD 是「本次击杀致死」的正常结果，
必须走 SETTLED；「击杀前已死」（被他人先行击杀）的消散仍由看板/追凶/接令访问点的
sweep 负责。无令实体（直写 KV 兼容路径）不做此复核，旧口径逐值不变（验收 6 不变）。

### 常量（core/hunt.py，既有值不改）
- 既有：`SIN_THRESHOLD=80`、`HUNT_TTL_H=48.0`、击杀者功德 40 / 业力 −20、反悬赏 50 灵石/功德 20。
- 新增：`ORDER_MAX_HUNTERS=5`（单令接令人数上限）、`ASSIST_MERIT=15`（协剿功德，
  ≤ EVENT_EFFECT_CAPS["merit"]=40）、`TRACK_REFRESH_SECONDS=3600`（追凶情报刷新间隔）。

### 发布
- 触发：`ensure_order(target)` 在 format_board / accept / track / settle_kill 访问点惰性调用；
  target `is_marked` 且无 OPEN 令 → 建令（order_id、issued_at、expires_at=issued_at+48h、
  intel_region/intel_at 以发布时凶犯区域初始化）。
- 去重：同一 target 同时至多一 OPEN 令（KV 以 target_id 为键，结构性去重）。

### 接令（/接令 = /接除凶）
- **同名消歧（评审 M1 裁定）**：`/接令` 在基线已被悬赏板占用（`/接令 <告示编号>`，两端均
  要求纯数字参数）。双端统一按参数消歧：纯数字 → 悬赏板既有接令；非数字道号 → 除凶接令。
  网页两颗「接令」按钮（悬赏=编号、除凶=道号）由此各行其道，悬赏板口径零改动。
- 旧校验全保留（目标存活、非自己、is_marked、每猎手 1 令、48h TTL、宗门环钩子在 server 层）。
- 换接他令时先摘除旧令登记（一人一令在令侧同样成立）；协剿资格在结算时回验猎手当前记录。
- 新增：令侧登记 hunters[hunter_id]=accepted_at；令满 `ORDER_MAX_HUNTERS` 且本人不在令中 → 拒绝
  （文案明示人数已满）；本人已在令中重复接令 → 按旧行为刷新自己的猎手记录，不重复占位。

### 追凶（/追凶，新指令）
- 前置：本人有未终结的接令记录；否则提示先接令。
- 情报口径：只给**区域级**情报（`MarketEngine.region_of(地点)`），不给精确地点；
  情报为快照：距上次刷新 < `TRACK_REFRESH_SECONDS` 时返回快照区域并注明情报时龄，
  ≥ 间隔时刷新为凶犯当前区域后返回。附：令状态、剩余时限、接令人数、自己是否为协剿位。
- 若访问时令已过期/消散/凶犯已死：惰性推进终态并如实告知，猎手记录一并清理。

### 围剿与结算（settle_kill 追加层，旧口径零改动）
- 旧结算原样：击杀者功德 +40、业力 −20、版图 hunt 钩子、世情播报、反悬赏清理、返回
  `{"merit":40,"sin_reduced":20}`。
- 业力消解口径（QA-01 裁定）：「业力 −20」由 `KarmaLedger.add_merit(40)` 的账本语义
  自带消解（40//2=20）实现，**总消解恰 20**，与自报 `sin_reduced=20` 一致；业力不足
  20 时按账本 max(0,·) 钳制（实际消解 = 当前业力值）。禁止在 add_merit 之外再叠加
  显式业力扣减（原实现双路叠加总消解 40，已修复并逐值对账，见 tests/test_hunt_qa_fix.py）。
- 洗清后击杀的主诛旧赏（QA-02 裁定）：OPEN 令的目标在结算前已洗清（不再 is_marked）
  时，令走 DISSOLVED（清全部猎手记录、不发协剿），且**主诛者的除凶旧赏（功德 +40 与
  业力消解）不发放**——旧赏是「除凶」之赏，须以击杀时目标仍为凶犯为前提；返回值
  `{"merit":0,"sin_reduced":0,"assists":[],"dissolved":True}` 如实标注。combat_fate 的
  代天除凶/杀人夺宝等其他通道结算与本裁定无关、不受影响；版图 hunt 钩子与除凶世情
  播报在此路径同样不触发（未发生除凶结算）。
- 反悬赏清理语义（QA2-01 裁定）：settle_kill 的反悬赏清理块位于 SETTLED /
  DISSOLVED 分叉之前、两路共用，删除全部与死者相关的 `counter_hunts` 条目：
  死者作为猎人的条目（键 == victim.id 或 `hunter_id == victim.id`，其反杀机会
  随死消散）与死者作为被反悬赏目标的条目（`target_id == victim.id`，键在他人
  名下，目标既死便永不可触发）；与死者无关的条目（他人之间的反悬赏）不动。
  原实现只清「死者作为猎人」方向，目标方向条目无界残留，已修复并有回归
  （tests/test_qa2_hunt_spillover.py 两例：SETTLED / DISSOLVED 后 target 方向
  全清；tests/test_qa2_fix_regressions.py 补猎人方向同存全清、无关条目保留、
  非 dict 脏条目容错）。
- 追加：若 victim 有 OPEN 令——同场（location == victim.location）、存活、已登记接令、
  非击杀者本人、非 victim 的猎手，各得协剿功德 +`ASSIST_MERIT`（现读现存、逐个落账）；
  令置 SETTLED（记 settled_by/settled_at）；清除**全部**猎手指向 victim 的 `hunts` 记录。
  返回 dict 追加 `assists: [{name, merit}]`（加法字段，旧调用方只读 merit/sin_reduced 不受影响）。
- 幂等：`settle_kill` 二次调用因猎手记录已弹仍返回 None（旧行为）；令已 SETTLED 时不重复发协剿。
- 无令实体（直写 KV 的兼容路径）：跳过追加层，旧口径完整生效。

### 弃令（/弃令 = /弃除凶）
- 旧行为 + 同步从令侧 hunters 摘除本人；令本身不因弃令终结（其他猎手继续）。

### 死亡/闭关口径（对齐 F07 委托）
- 双端四指令（/除凶 /接令 /追凶 /弃令）均**不进闭关白名单**（闭关锁门，server med_ok 与
  CLI 白名单均不含）。说明：与 /告示（纯看板）在 server 端放行不同，除凶四指令含个人令状态
  与动作，按 F07「同组锁门」口径整组对齐。
- 凶犯死亡走 SETTLED/DISSOLVED 惰性终态；猎手死亡后其记录由令终态/过期统一清理，
  不单独挂钩死亡结算（与既有 `hunts` 惰性过期同口径）。

## 三、去重对齐对照表（同一击杀的全部通道）
| 通道 | 触发事实 | 奖励 | 与除凶令关系 |
|---|---|---|---|
| 除凶令（本项） | 接令者击杀令上凶犯 | 击杀者功德+40/业力−20（既有）；同场接令协剿者功德+15（新增） | 系统功德主通道 |
| 悬赏板 bounty | 击杀被玩家悬赏者 | 灵石（**玩家出资**）+ 功德 15/令 | 独立资金源，可同杀叠加（既有口径不动） |
| combat_fate 代天除凶 | 任何人击杀血煞者 | 功德+60 | 既有口径不动 |
| 宗门环 hunt | **接除凶令成功**（非击杀） | 贡献+8/功德+2/灵石50（日环） | 接令计数，与击杀结算无关 |
| F07 委托除妖环 | 探险成功计数 | 链尾一次性灵石/功德/线索 | 与直接击杀无关 |
| F09 版图 hunt | hunt.settle_kill 结算点 | 猎手本宗事发区域影响力+10 | 计数型，无资金 |
| F14 不攻诺 | 出手事实 | 诺言践/毁结算 | 事实钩子，无击杀奖励 |
原则：**灵石主奖励只有悬赏板一条（玩家出资）**；功德各通道为既有口径，F15 唯一新增为
协剿功德 +15（封顶内、仅同场接令者、每令每人一次）。

## 四、Out of Scope
- 玩家/宗门出资发布除凶令（发布只走规则阈值惰性生成；出资悬赏已有悬赏板）。
- 改动悬赏板、combat_fate、宗门环、委托、版图的任何既有数值与口径。
- 围剿战斗系数（1.15 既有）调整；NPC 自动接令/协剿 AI 行为。
- 追凶精确地点情报、跨令组队系统、除凶排行榜。

## 五、验收标准
1. 凶犯达阈值后首次访问即有 OPEN 令；同凶犯重复访问不重复发令。
2. 接令登记令侧，满 5 人拒绝第 6 人；弃令摘除登记；每猎手 1 令旧约束不变。
3. /追凶 只给区域级快照情报，刷新间隔 3600s 内返回旧快照、过间隔刷新；双端一致。
4. 击杀结算：击杀者旧赏逐值不变；同场接令协剿者各 +15 功德；不在场/未接令者无份；
   令 SETTLED 后二次结算零重复发放；全部猎手记录清除。
5. 令到期 → EXPIRED、凶犯洗清/已死 → DISSOLVED，均惰性推进且清猎手记录，无悬挂。
6. 无令实体兼容路径（直写 hunts KV）结算与旧行为逐值一致（test_atlas/test_wave2 不破）。
7. 双端四指令可用且闭关锁门；网页有除凶入口；零新增 AI 调用。
8. 新增 tests/test_hunt_state.py 覆盖上述；全量回归 0 失败。
9. （QA 复测轮追加）洗清后未经任何访问点直接 settle_kill：令 DISSOLVED、协剿 +0、
   主诛者除凶功德增量 0、猎手记录全清（tests/test_qa_cross_karma.py +
   tests/test_hunt_qa_fix.py）；血煞未清（仅业力归零）与先置 DEAD 的正常击杀不被误判。
10. （QA 复测轮追加）业力总消解逐值对账：sin ∈ {0,5,10,19,20,21,30,39,40,41,100}
    结算后业力恰为 max(0, sin−20)，功德恰 +40，自报 sin_reduced=20 与落账一致。
