# Core-V2 换心重构：实体道具、空间拓扑网与新一代探险藏宝系统

## Problem
1. 现有背包系统为字符串列表 `List[str]`，无法承载装备词缀、耐久、动态属性、以及藏宝图附带的真实坐标、谶语与谜题元数据；
2. 地图为 `config.py` 中的静态字典 `WORLD_LOCATIONS`，缺乏空间距离与路网拓扑，无法支持动态环境异变（世界疤痕）、资源演化或秘境降世；
3. 挖宝系统为单次随机掷骰（刮刮乐），缺乏探索感、无地点校验、无多玩法分支，完全脱离了网游小说式奇遇与智斗破局的沉浸体验。

## Design
1. **实体道具模型 (`core/items.py`)**：
   - `ItemEntity`：含 `uid`, `name`, `kind`, `tier`, `stats`, `affixes`, `lineage_lore`, `custom_metadata`；
   - 原生支持装备随机词缀、丹药效用、以及携带空间坐标与谜题原型的实体藏宝图。
2. **空间拓扑图谱 (`core/world_grid.py`)**：
   - `WorldNode`：包含相对坐标、物理连通邻接节点、实时灵气浓度、危险度评级；
   - 动态环境状态栈 (`EnvironmentState`)：原生支持「世界疤痕」的施加、属性修正与 TTL 自然自愈。
3. **新一代探险与藏宝系统 (`core/treasure_system.py`)**：
   - 实体藏宝图生成与地点绑定；
   - `/宝图` 查阅线索与谶语；
   - 真实空间节点校验；
   - 多玩法原型支持（战斗伏击、纯规则五行阵盘解谜）；
   - AI DM 跑团式自由语裁决（`/做`）与 Fail Forward（向前失败）机制；
   - 破坏性行动引发的「世界疤痕」与全服异象广播。
4. **指令集成与表现**：
   - 适配 `command_catalog.py`，无缝接入 CLI 终端与 Web 单轨工作台。

## Out of Scope
- 3D 渲染与大型地图编辑器；
- 复杂的跨服多进程架构；
- 商业付费系统（仙晶/月票）。

## Acceptance Criteria
- [x] AC1: `ItemEntity` 能够完整定义并序列化，支持装备词缀与藏宝图专属元数据；
- [x] AC2: `WorldGrid` 构建出具备空间邻接关系的节点路网，能计算两点间距离与路径；
- [x] AC3: `WorldGrid` 能对节点注入「世界疤痕」，改变节点显示别名、危险度与灵气，并在到期后自愈；
- [x] AC4: 掉落并使用实体藏宝图，能正确解析线索谶语，若不在目标节点则提示地理方位偏差；
- [x] AC5: 在目标节点执行挖宝，可触发【五行阵盘解谜】或【凶地守护伏击】，给出规则确定的结果与掉落；
- [x] AC6: 挖宝支持自由行动（`/做`），通过 AI DM 意图解析与规则检定，支持 Fail Forward 奇遇；
- [x] AC7: 破坏性破局成功在节点留下世界疤痕并广播世界频道；
- [x] AC8: 所有单元测试与集成测试通过，覆盖率高且无回归破坏。
