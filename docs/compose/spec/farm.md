# F06 灵田/洞府经营 Spec

> 上位文档：docs/compose/spec/feature-completion.md（F06）。基线：2d905a0（F01–F05 已合，全量 322 passed）。
> 创作者已授权「直接改、无需逐项确认」，本 spec 即阶段一细化结论（requirement-evaluator 五步收敛）。

## 需求本质与核心诉求
- **表层需求**：洞府从文案概念变成可经营资产：开辟洞府 → 灵田播种 → 墙钟生长 → 收获入囊；
  洞府等级给闭关小幅加成。
- **本质意图**：补一条「灵石沉淀 → 时间转化 → 产出回流」的慢经济线：与探险（即时、风险）、
  跑商（空间价差）、典当（抵押周转）区分开，灵田是唯一的「时间型」产出；洞府同时是灵石 sink
  （开辟/升级一次性大额消耗）与闭关体验的长期投资（寿元经济闭环约束 3 的正面回答）。
- **关键目标**：开辟/播种/收获/升级四步闭环可玩通且收益口径可复算；闭关加成有独立封顶、
  在连乘链中只贡献一个有界因子；旧档零破坏；死亡随世终结（与 F01 同口径）。

## 现状盘点（实测，2026-11-04）
- **「洞府」只是文案**：grep 命中多为闭关文案（clock.py「遁入洞府」）、宗门地点名（宗门玄元洞府）、
  NPC 议程文本与 name_guard 词表，无任何角色洞府状态/经营逻辑。闭关本身在任意地点可进行，
  地点只给 density 与 rent（clock.py settle/start）；归隐是庇护态（protection.py），与洞府无关，不复用。
- **闭关结算连乘链**（`WorldClock.settle_meditation`，core/clock.py）：
  raw_gain = 基础率 × 有效小时 × 灵根效率（≤2.5）× 地点 density（≤3.0）× 全服灵气 qi（≤1.0，只稀释）
  × 自创功法 art_mult × 心法主修 slot_mult（F02，≤1.10）× 新手 newbie（2.0，限时）
  × 丹药 pill_mult（≤1.5）；其后再乘碎石 stone_bonus（≤2.0）与心境 event（≤1.6）。
  本项在 slot_mult 之后、同一乘积内追加洞府因子 cave_mult。
- **物品与价格带**：ITEM_CATALOG 有 百年灵芝（material，55）、聚气丹（40）、回春露（22）、妖兽内丹（80）；
  商会购买对任意目录物品开放（buy_from_guild，非 pill/array 走 else 分支入 inventory），
  故新增 kind="seed" 条目即天然可买、入行囊；区域价对未登记产地的物品回退系数 1.0（不炸）。
- **探险收益量级**：盘缠 20/次，灵石增量上限 = ADVENTURE_STONES_BASE ×(1+境界×0.5)×危险系数，另有掉落物。
  灵田单产净收益须与之同量级或更低（见校准表），且灵田是纯时间产出、无风险无盘缠，理应更慢。

## 关键设计决策（与备选对比）
1. **洞府落点：开辟限定安全区，经营不限地点**。开辟是「在此地结庐」的世界锚定行为，
   要求 WORLD_LOCATIONS[location].is_safe（与归隐的地点口径一致）；开辟后洞府随身（洞府令牌观照），
   播种/收获/升级/查看不限地点——与 F01 灵宠「随行管理」同理，避免玩家被绑死在一个地点反复迁跃。
   备选「开辟也不限地点」否决：安全区限定给地点系统留一个真实用途，且防冲突区扎营刷田。
2. **洞府状态存角色字段（不建表）**：`cave_level: int = 0` + `farm_plots: List[FarmPlot]`
   （pydantic 新模型，字段 crop/planted_at/matures_at），旧档 JSON 无此二字段自动补默认（F01/F02 先例）。
   地块数由等级推导（CAVE_PLOTS_PER_LEVEL×等级），farm_plots 长度由引擎 `_plots()` 惰性对齐
   （只补空地块、永不截断已有作物；等级永不下降故无截断场景）。
3. **种子只走行囊**：播种消耗 inventory 中的种子（坊市 /购买 入囊，与丹药同路径），
   不在播种指令里直接扣灵石买种——购买与种植解耦，种子也可经寄售/掉落流通。
   作物表 FARM_CROPS 在 core/farm.py 单点定义（种子名 → 产出物/时长/产量区间），
   种子与产出物条目进 ITEM_CATALOG（kind 分别为 seed/material），价格与产地（TRADE_ITEM_ORIGIN）一并登记。
4. **收获惰性、无后台线程**：成熟只看墙钟时间戳（matures_at），/洞府 与 /收获 时现算状态
   （F04/F05 惰性结算先例）；测试注入 now 即可确定性覆盖未熟/成熟/过熟三态。
5. **过熟从简：过熟减产不枯死**。成熟后 CAVE_WITHER_SECONDS（24h）内产量不变；
   超过则产量 −1（下限 1）并在面板/收获文案标注「过熟」。备选「枯萎归零」否决：
   灰度期玩家上线频率不稳，归零惩罚过重；减产已足够表达时间管理。
6. **闭关加成接入位序与封顶**：cave_mult 在连乘链中置于 slot_mult 之后（与心法同段，均为「修行环境/法门」类因子），
   值 = 1 + CAVE_MEDITATION_BONUS[level]，表驱动 {1:0.02, 2:0.04, 3:0.05}，硬顶 +5%。
   **全链极值论证**：连乘是可交换的，洞府因子的边际贡献恒等于其自身值（≤×1.05），
   不与任何其他因子产生交叉项；其余有界因子 slot ≤1.10、pill ≤1.5、newbie 2.0（新手期限定）、
   stone ≤2.0、event ≤1.6 均为存量封顶，本项不改动。因此加洞府后全链相对增幅恰为 ≤5%，不存在叠加失控。
7. **闭关门禁（F01 先例）**：/洞府 查看进双端闭关白名单（纯只读：状态由时间戳现算，零写状态）；
   /开辟 /播种 /收获 /升级洞府 不进白名单（闭关锁门），且引擎层对四条管理指令另做 MEDITATING 拒绝（双保险，
   防未来白名单误放行直接改状态）。DEAD：管理指令拒绝，查看放行（遗容，标注荒废）。
8. **死亡口径（与 F01 同构）**：`FarmEngine.on_owner_death(char)` 清空全部地块作物（灵田荒废），
   cave_level 保留在旧世记录上仅作遗容；转世是新 Character（cave_level=0、无田），
   在 server `_settle_if_needed` 与 CLI 死亡结算两处与 PetEngine.on_owner_death 并列挂钩。

## 完善后的规则闭环（行为契约）
### 常量（core/farm.py，对照坊市物价校准）
- `CAVE_MAX_LEVEL = 3`
- `CAVE_OPEN_COST = 300`（开辟至 1 级；约 7.5×聚气丹价、新号初始灵石 100 的 3 倍——中前期目标而非开局消费）
- `CAVE_UPGRADE_COST = {2: 500, 3: 900}`（升至该等级的灵石成本，递增）
- `CAVE_PLOTS_PER_LEVEL = 2`（地块数 = 等级×2：2/4/6）
- `CAVE_MEDITATION_BONUS = {1: 0.02, 2: 0.04, 3: 0.05}`（闭关修为加成，硬顶 +5%）
- `CAVE_WITHER_SECONDS = 86400`（成熟后 24h 起过熟减产）
- 作物表 `FARM_CROPS`（种子 → 产出/生长秒/产量区间）：
  | 种子（价） | 产出（价） | 生长 | 产量 |
  |---|---|---|---|
  | 灵谷种子（10） | 灵谷（15） | 1800s（30 分） | 2–3 |
  | 聚灵草种子（18） | 聚灵草（28） | 3600s（1 时） | 2–3 |
  | 灵芝种子（30） | 百年灵芝（55） | 14400s（4 时） | 1–2 |

### 收益校准（基准区、商会回收 0.5 口径，期望值）
- 灵谷：种子 10 → 期望产出 2.5×15×0.5 ≈ 18.8 灵石 → 净 ≈ **+8.8 / 30 分 / 地块**
- 聚灵草：种子 18 → 2.5×28×0.5 = 35 → 净 ≈ **+17 / 1 时 / 地块**
- 百年灵芝：种子 30 → 1.5×55×0.5 ≈ 41.3 → 净 ≈ **+11.3 / 4 时 / 地块**
- 满配（3 级 6 地块全聚灵草）：≈ +102 灵石/时（须每时上线收播），而开辟+两次升级共沉淀 1700 灵石，
  回本 >16 小时完美耕作；且收获物若出售还吃 F03 同货同日收购量回归压价。探险单次灵石上限随境界
  增长且附带掉落/遇兽，跑商价差为百分比杠杆——灵田收益不碾压任一线，定位「慢而稳」。
- **跨系统套利面（自查）**：收获物即普通 inventory 物品——异地出售吃 F03 区域系数（与跑商同池，
  非新增通道）；典当收获物与出售同为五折（F04 口径，弃赎不优于出售）；种子只能买/流通不能自产，
  不存在「种→收→种」自循环印钞（产出物均不可播种，FARM_CROPS 键只有种子名）。

### 数据（core/models.py，只加带默认值的字段）
- `FarmPlot`：crop（种子名，空=空地）、planted_at、matures_at。
- `Character.cave_level: int = 0`、`Character.farm_plots: List[FarmPlot] = []`。

### 引擎（core/farm.py · FarmEngine，规则单点）
- `plots_capacity(c) -> int`、`meditation_mult(c) -> float`（无洞府恒 1.0；settle_meditation 以 try 包裹调用，
  与 art/slot 同模式，异常回退 1.0 不炸结算）。
- `open_cave(c, now=None)`：DEAD/MEDITATING 拒绝 → 已有洞府拒绝 → 非安全区拒绝 → 灵石不足拒绝；
  成功扣 300、cave_level=1、地块对齐。
- `upgrade_cave(c, now=None)`：无洞府/已满级/灵石不足拒绝；成功扣对应成本、等级+1、地块对齐（保留已有作物）。
- `sow(c, seed_hint, count=1, now=None)`：无洞府拒绝；种子名子串模糊匹配行囊实物且必须在 FARM_CROPS 中
  （囊中有但不可种 → 专属文案；囊中无 → 无此物文案）；逐块播种：每块消耗 1 颗种子，
  planted_at=now、matures_at=now+grow_seconds；空地不足/种子不足时**部分成功**（播满可播的并明示数量），
  一颗都没播成则整体失败不改状态。
- `harvest(c, now=None, rng=None)`：无洞府拒绝；遍历地块，成熟者逐块掷产量（rng 可注入），
  过熟减产（−1，下限 1）并标注；产出 append inventory、地块清空；无成熟作物 → 失败文案（列最近成熟倒计时）。
- `panel_text(c, now=None)`：等级/地块总数/闭关加成/升级成本预告 + 每块状态
  （空闲 / 生长中（余时）/ 已成熟 / 过熟）+ 未开辟时的开辟指引。DEAD 时首行标注「洞府已随旧世荒废」。
- `on_owner_death(c)`：清空全部地块（crop/时间戳归零），等级保留（遗容）。

### 闭关接入（core/clock.py · settle_meditation 一处）
- 在 slot_mult 计算后追加：`cave_mult = FarmEngine.meditation_mult(character)`（try 包裹，失败 1.0），
  raw_gain 乘积追加 `* cave_mult`。无洞府角色 cave_mult 恒 1.0 → 旧结算逐字不变（有回归测试钉住量级）。

### 指令（server/world.py 与 cli/main.py 双端一致，成功才 CharacterRepository.save）
- `/洞府`（/cave）：面板。`/开辟`（/opencave）：开辟。`/播种 <种子名> [数量]`（/sow）：播种。
  `/收获`（/harvest）：收获全部成熟地块。`/升级洞府`（/upgradecave）：升级。
- server 帮助行与 CLI 帮助各加一行；server 闭关白名单加 /洞府 /cave，CLI 闭关白名单同。

### 网页
- web/index.html 新增「洞府灵田」卡（置灵宠卡后）：洞府（data-cmd /洞府）、开辟（data-cmd /开辟）、
  播种…（data-prompt，prefix /播种，placeholder「种子名 [数量]」）、收获（data-cmd /收获）、
  升级洞府（data-cmd /升级洞府）；web/app.js hints 加 播种 一条。
- _status_dict 新增 `cave`（{level, plots_total, plots_used, mature}，无洞府为 None，纯新增）。

### AI 边界
- 零新增 AI 调用：全部文案本地模板。

## 边界与异常
- 灵石不足（开辟/升级）/ 已有洞府重复开辟 / 满级再升级 / 无空地 / 无种子 / 种子不可种 /
  未成熟收获 / 闭关中管理（双端白名单 + 引擎双拒）/ DEAD 管理拒绝、查看放行 /
  开辟时不在安全区 / 播种数量参数非法（非数字 → 按 1 处理并以整串匹配种子名为先，与 F01 参数解析惯例一致：
  末 token 为正整数时才拆作数量）。
- 并发：server handle 世界锁串行；CLI 单进程。引擎先校验后改状态，失败不落改动（部分播种除外，见契约明示）。
- 旧档兼容：纯角色新字段（带默认值），无新表无改表；无洞府角色 settle_meditation 结果与旧版一致。
- NPC：不参与灵田（玩家专属经营线），种子 NPC 不受影响。

## 验收标准
1. tests/test_farm.py 覆盖：开辟（灵石不足失败/非安全区失败/成功扣 300 与地块数）、
   播种（无洞府/无种子/不可种物品/无空地/批量部分成功）、未成熟不可收、成熟收获产量区间与入囊、
   过熟减产、洞府闭关加成数值断言（无洞府=旧口径、1/3 级倍率、与心法主修同时存在的连乘口径）、
   升级（成本递增/地块扩容/满级拒绝/作物保留）、死亡后新世无洞府 + on_owner_death 荒废、
   旧档反序列化兼容、server handle 至少 1 条全链路（含闭关锁门与 /洞府 查看放行）。
2. 全量回归 0 失败（基线 322 + 新增）。
3. 独立评审子代理审 diff（重点：连乘极值、即种即卖与 F03/F04 跨系统套利），必须修项整改后复跑全量。

## Out of Scope
- 灵田灌溉/施肥/灵气浓度影响产量、洞府选址迁移、洞府防御/被攻破（combat 中洞府大阵是既有战斗文案，不动）。
- 作物加工链（炼丹配方新增）、灵田雇工/自动播种、洞府访客/合租。
- 灵谷/聚灵草的食用/炼丹用途（本项只入目录作可售材料；用途接入留后续功能）。
- NPC 种田、洞府排行榜、网页独立洞府面板页（卡片按钮 + 指令面板即达最小闭环）。
