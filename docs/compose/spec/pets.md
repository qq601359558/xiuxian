# F01 灵宠系统 Spec

> 上位文档：docs/compose/spec/feature-completion.md（F01）。基线：a609711（244 passed）。
> 创作者已授权「直接改、无需逐项确认」，本 spec 即阶段一细化结论（requirement-evaluator 五步收敛）。

## 需求本质与核心诉求
- **表层需求**：给玩家一个可捕获、可养成、可助战的灵宠系统，形成新养成线。
- **本质意图**：补一条「探险 → 遇兽 → 投入资源养成 → 反哺斗法/探险」的资源循环，
  让探险收益不止于一次性掉落，灵石/丹药多一个长期消耗口（寿元经济闭环约束 3）。
- **关键目标**：最小闭环可玩通：遇兽 → 契约 → 喂养成长 → 出战助战 → 放生/随主殁。

## 可行性诊断与系统影响
- **技术可行性**：高。角色是 pydantic 模型，加带默认值字段即旧档兼容；
  战力接入点现成（CombatEngine.calculate_power 已乘 EquipEngine.power_bonus，
  同模式加 PetEngine.power_bonus）；探险结算在 AdventureEngine.explore 单点落账，易挂钩子。
- **系统影响面**：core/models.py（新模型+字段）、core/pets.py（新引擎）、
  core/combat.py（战力乘子+战报一行）、core/adventure.py（遇兽骰+助战行）、
  server/world.py（6 指令+status pet 字段+死亡结算钩子）、cli/main.py（6 指令）、
  web（按钮卡+命盘一行）。不动表结构、不动既有数值常量。

## 潜在不足、盲区与风险
1. **[存档兼容]** 旧档 JSON 无 pets 字段 → pydantic 默认值必须兜底，并有反序列化测试。
2. **[数值膨胀]** 助战加成若与装备/功法叠加失控会破坏斗法平衡 → 单独封顶 +10%，
   量级对齐 EquipEngine（+20%）的一半以下。
3. **[刷宠]** 反复探险刷遇兽 → 遇兽只在探险成功时掷骰（18%），且已有探险冷却与盘缠；
   待契约灵兽同时只存 1 只（新遇覆盖旧遇），养宠上限 3 只。
4. **[状态一致]** 出战唯一性必须由引擎单点维护（deploy 时清其他 active），不能靠前端。
5. **[死亡语义]** 一世循环：主人坐化结算时灵宠殁；转世新角色 pets 为空（新 Character 默认）。
6. **[闭关/死亡态]** 死亡角色一切灵宠操作拒绝；闭关中可管理（查看/喂养/出战/休息），
   契约需身处野外遇兽语境，闭关中拒绝契约（与探险同理锁门）。

## 完善后的规则闭环（行为契约）
### 数据
- `SpiritPet`：species（物种）、name（个体名，默认同物种，重名自动加序）、
  growth（成长值）、intimacy（亲密度 0~100）、active（是否出战）、
  state（follow 随行 / rest 休息 / dead 已殁）、met_at（结契时间戳）。等级由 growth 推导（level_for）。
- `Character.pets: List[SpiritPet] = []`；`Character.pending_pet_species: str = ""`（待契约灵兽，单只）。

### 物种池（core/pets.py 常量，各有规则倾向）
| 物种 | 倾向 | 效果 |
|---|---|---|
| 青鳞蟒 | 攻 | 出战战力加成（全额） |
| 疾风隼 | 攻 | 出战战力加成（全额） |
| 玄甲龟 | 守 | 出战战力加成（全额） |
| 寻宝鼠 | 探宝 | 战力加成减半；探险成功时额外拾获掷骰 |

### 常量（core/pets.py，对照坊市物价校准）
- `PET_MAX_OWNED = 3`、`PET_MAX_LEVEL = 10`、`PET_GROWTH_PER_LEVEL = 100`
- `PET_CONTRACT_STONES = 60`（约 1.5×聚气丹价 40；探险盘缠 20 的 3 倍）
- `PET_FEED_STONES = 15` → 成长 +10、亲密 +3；丹药喂养（消耗囊中 kind=pill 丹药 1 颗）→ 成长 +25、亲密 +6
- `PET_ENCOUNTER_CHANCE = 0.18`（探险成功后掷骰）
- `PET_TREASURE_LOOT_P = 0.25`（探宝宠额外拾获概率，至多 1 件，走既有掉落表）
- 战力加成：`min(0.10, 0.02 + 0.01 × level)`（1 级 +3%，8 级起 +10% 封顶）；探宝宠减半；
  亲密度 < 20 的灵宠不肯出力（加成 0，文本提示）。

### 指令（server 与 cli 双端一致）
- `/灵宠`：面板（待契约提示、每只灵宠的物种/等级/成长/亲密/状态、出战标记）。
- `/契约 <兽名>`：须有待契约灵兽且名称匹配（子串模糊，与 /穿戴 同惯例）；扣灵石；
  满 3 只拒绝；成功后清空待契约、灵宠入册（默认休息态，不自动出战）。
- `/喂养 <宠名> [丹药名]`：无丹药名时扣灵石喂养；带丹药名时消耗囊中该丹药。
- `/出战 <宠名>`：设为唯一出战（其余自动休息随行态切换：被换下的回 rest），state=follow。
- `/休息 <宠名>`：取消出战，state=rest。
- `/放生 <宠名>`：移除灵宠（出战中放生则无出战宠）。
- 通用：宠名子串模糊匹配；找不到/重名歧义（匹配多只）时报错列出候选。

### 助战
- `CombatEngine.calculate_power` 乘 `PetEngine.power_bonus(c)`（try 包裹，与装备同模式）。
- 探险：出战宠随行文本写入结算行；探宝宠额外拾获；出战宠每次探险成功成长 +2（封顶）。
- 斗法战报：execute_ambush 结果文本中，出战宠在场时加一行助战描述（攻/守/探各一句模板）。

### 遇兽
- AdventureEngine.explore 成功结算后：`PetEngine.maybe_encounter(c, rng)` 掷骰，
  命中且养宠未满 → 写入 pending_pet_species 并在结算文本与返回 dict（pet_encounter）中播报。
  已有未契约的待契约灵兽时不重复触发（先契约或等其散去——新探险成功有 50% 使旧待契约灵兽遁走，防占位锁死）。

### 死亡
- server `_settle_if_needed` 调用 `PetEngine.on_owner_death(char)`：全部灵宠 state=dead、active=False；
  面板可见「已殁」。新一世（新 Character）无灵宠。

### 网页
- _status_dict 新增 `pet`（出战灵宠 {name, species, level, intimacy} 或 None）与 `pets_count`（纯新增）。
- 命盘 kv 加一行「灵宠」`<dd id="stPet">`，app.js applyStatus 渲染（无出战时显示「—」或休息只数）。
- 右栏新增「灵宠」卡：/灵宠 查看、契约…、喂养…、出战…、休息…、放生…（data-cmd/data-prompt 既有模式）+ app.js 提示文案。

### AI 边界
捕获概率、成长、加成、成本全部规则裁决；叙事只用本地模板（遇兽/助战文案），
不依赖 AI，无 AI 模式完整可玩。灵宠命名默认物种名，不走 AI 生成（防命名审核面扩大）。

## Out of Scope
- CLI 端不新增探险（探险本来就是局域网专有，见 cli 帮助）；CLI 六指令齐全，
  待契约状态与 LAN 共享同一角色存档。
- 灵宠繁殖、进化、技能学习、灵宠对灵宠战斗、交易灵宠。
- 灵宠专属丹药（饲灵丹）上架坊市——喂养先复用既有丹药与灵石。
- 前端灵宠独立面板页（命盘一行 + 指令面板即达最小闭环）。

## 评审整改（独立 Review 后，2026-11-03）
- **[必须修] 闭关门禁双端白名单**：server `handle` 与 CLI 的闭关锁原本拦截全部灵宠指令，
  与本 spec「闭关中可管理（查看/喂养/出战/休息）、仅契约拒绝」冲突。已双端放行
  /灵宠 /喂养 /出战 /休息（含英文别名）；/契约 /放生 仍被门禁拦截（契约另有引擎层拒绝）。
  新增闭关态 handle 全链路用例。
- **[建议修] 待契约遁走播报**：maybe_encounter 改结构化返回 {species, fled}，探险结算追加遁走行。
- **[建议修] 探宝额外拾获口径**：掉落表单次掷骰约 37% 空手，已改为重掷至非空（至多 5 次），
  名义 25% ≈ 实际额外拾获 1 件的概率。
- **[建议修] 喂养参数解析**：双端共用 core.pets.split_feed_args（整串先匹配宠名，
  否则末 token 在物品目录时拆作丹药名透传引擎裁决），写错/非丹药给出引擎的准确报错。
- **[建议修] 成长封顶**：PET_GROWTH_CAP=900（满级阈值）；满级且满亲密时喂养拒绝不扣费。
- **[知晓] 丹药喂养效率高于灵石喂养**（如回春露 22 灵石换 +25 成长）：有意设计——
  丹药是需购买/掉落的稀缺物，灵石喂养是保底入口，不作平衡处理。
- 补测：重名加序、主人 DEAD 引擎拒绝、带宠序列化往返、斗法助战行、handle 丹药喂养。
