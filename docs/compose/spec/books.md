# F11 著书立说 Spec

> 总纲：`docs/compose/spec/feature-completion.md` F11。基线：main 8c27500（F01–F10 已合并，全量 413 passed）。
> 核心不变：寿元硬通货、规则裁决数值、LLM 只写叙事（此处仅书名/序言）、一世循环。

## 一、需求本质解构（五步细化）

- **表层需求**：玩家把经历写成书，书流通，他人研读得少量修为/道心（一次性），作者得声望；AI 只写书名/序言。
- **本质意图**：给「阅历」一个可消费的出口，把单人经历变成可流通、可被他人消费的社交资产，形成「耗寿著书 → 流通 → 他人受益 → 作者扬名」的长线声望闭环，与寿元经济挂钩（著书烧寿元，逼玩家在长生与留名之间取舍）。
- **验收标准**：见第六节，逐条有测试证据。

## 二、现状盘点（实现前实测结论）

1. **研读/功法书机制**：全仓无 `/研读` 指令、无读书机制。功法习得走 skills 列表 + 心法槽位（F02），不消耗书类物品；`ITEM_CATALOG` 无书/简类条目（仅丹药/材料/种子/装备/阵盘/藏宝图）。→ `/研读` 为新设指令，无既有口径可复用，闭关口径与 `/著书` 对齐（见第五节）。
2. **修为/道心通道**：修为 = `realm.current_exp`，事件通道钳制 `min(max_exp, cur+exp)`（core/events.py:137）；EVENT_EFFECT_CAPS：exp 800、dao_heart 变动绝对值 20、merit/sin 40。道心 = `karma.dao_heart`，既有改法一律 `max(0, min(100, …))` 钳制。→ 研读收益沿用同一钳制口径，量级远低于 caps。
3. **声望字段**：角色**无个人声望字段**。既有「声望」只有 F08 议政的宗门级 `sect_state:{sect}.prestige`（宗门维度，不可挪用）；个人侧最接近的是功德 `karma.merit_value`（因果账语义，除恶/护法所得，挪作「读书扬名」会污染因果账与道行榜口径）。→ 新增 `Character.prestige: int = 0`（带默认值，旧档自动补），专表个人声望，本功能为其首个产出通道。
4. **灵感/阅历计数**：角色**无任何累计计数**（无探险/击杀/事件计数器）。`event_ledger` 表虽按 actor 记事，但覆盖不全（探险成功不入账、仅部分系统写），以其行数当灵感既不可靠也不可测。→ 按总纲兜底口径：新增 `Character.inspiration: int = 0`（带默认值）+ 三个既有事实落账点的计数钩子（探险成功 +1 / 委托链完成 +2 / 突破成功 +3，均 try/except 包裹、与 F09 版图钩子同段位），禁止凭空发放。
5. **流通通道**：坊市有**玩家寄售**全套（`MarketEngine.list_item/cancel_listing/buy_listing` + `market_listings` 表 + 双端 `/寄售 /买寄售 /撤单`），且 F04 没收物亦经此流通。→ 书的流通选**玩家寄售**：复用担保成交/货款结算，不新造通道。同场赠予（chat gift）为次通道（见 7）。
6. **物品实例问题**：`inventory` 是 `List[str]` 纯名列表，**无实例 id**；寄售转移的也只是名字。动态书若只靠物品名必然串本。→ 解法（本 spec 核心决策）：
   - 物品层：固定名物品 `亲笔手稿`（常量 `BOOK_ITEM`），**不入 ITEM_CATALOG**（入目录会被商会无限量贩卖无元数据的裸手稿，且污染行情板；寄售 `list_item` 对非目录物品有 kind_hint 兜底，流通不受影响）。
   - 元数据层：新表 `books`（只加新表，照 pawn_tickets 的 data_json 模式）存每「本」书：作者/书名/序言/品质/持有者/状态/已读名单/已结声望。
   - 绑定约束：**任一角色同时至多持有 1 本手稿**（自著未流通或购入的他人之作皆算；挂寄售中亦算持有）。著书、买寄售在入口处校验，绑定恒唯一，`/研读` 按 holder_id 唯一定位书目。
7. **次通道与逃逸口**：手稿是心血之作，只许寄售流通与交谈赠予（赠 NPC 后书随赠礼离场，书目置 `gifted` 终态——既有 do_gift 本就不把物品塞进 NPC 行囊，物品即被收下）。其余会让物品脱离绑定的通道一律在引擎单点拒绝：商会回收 `sell_to_guild`、NPC 专柜回收 `NpcShopEngine.sell`、典当 `PawnEngine.pawn_item`、拍卖 `AuctionEngine.list_item`、当面交易报价 `TradeEngine.set_offer`、宗门上交 `donate_item`（评审 M1 补全：后两者的脱离会令作者书目悬空——不能再著书/买书且无从处置，属永久砖化，必须拒绝而非 fail-closed 了事）。未挂钩的边缘转移（斗法掉落等）由「研读必须同时满足：行囊有手稿 ∧ 书目 holder 为本人」fail-closed 兜底——最坏结果是书变孤本不可读，绝不产生重复收益。

## 三、行为契约

### 3.1 灵感（inspiration）
- 来源（既有事实钩子，封顶 `INSPIRATION_CAP=60`，溢出不存）：探险成功 +1、委托链整链完成 +2、渡劫（大境界突破）成功 +3（小阶晋升不计）。
- 消费：著书一本耗 `BOOK_INSPIRATION_COST=10`。面板明示当前灵感与来源。

### 3.2 著书（/著书 写）
- 前置（任一不满足明确拒绝、零扣费）：存活（status 非 DEAD 且寿元未尽）；灵感 ≥ 10；寿元充裕——燃寿后须仍余 > `BOOK_MIN_REMAINING_YEARS=1.0` 年，即剩余寿元 > 成本 1.0 + 1.0；当前未持有任何手稿（含寄售中）。
- 成本：灵感 −10；寿元走既有 `lifespan.burn_lifespan(BOOK_LIFESPAN_COST_YEARS=1.0)`（与秘术燃寿同一路径，不新造扣减）。
- 产出：行囊 +`亲笔手稿`×1；`books` 表新建书目（holder=作者，state=held，readers=[]，prestige_paid=0）。
- 品质（规则先定，纯按成书时境界 tier）：tier ≤1 → 下品；tier 2–3 → 中品；tier ≥4 → 上品。
- 书名/序言：规则定品质后才起名。AI 可用时经 `ai.gateway._chat_text` 生成「书名 + 一句序言」（长度校验：书名 ≤14 字、序言 ≤80 字，不合格即弃用）；无 AI/失败/超时 → 本地模板池按品质抽取（rng 可注入）。AI 绝不参与品质与收益。

### 3.3 研读（/研读 [书名/作者名])
- 定位：读者须行囊有 `亲笔手稿` 且存在 holder 为本人、state=held 的书目；带参时书名/作者名须子串匹配该书，否则提示。
- 作者自读：可读（展示书名/序言/品质），**无任何收益**，不入 readers。
- 他人首次研读（每人对每本至多一次，readers 落账为准）：修为 +`READ_REWARDS[品质].exp`（下品 60 / 中品 150 / 上品 300，沿 events 口径钳至 max_exp）、道心 +1/+2/+3（钳 0–100）。同时结算作者声望（见 3.4）。
- 重复研读：只展示内容，零收益，文案明示「已研读过，心得不再重复」。
- 研读不消耗书：读后仍可寄售转手；下一手首次研读同理受益（按人计，不按本计——每位新读者各得一次，作者声望按本封顶防刷）。

### 3.4 作者声望（prestige）
- 每当一位新读者首次研读结算：作者 prestige += `PRESTIGE_PER_READ[品质]`（下品 2 / 中品 3 / 上品 5），但单本书累计结算 ≤ `BOOK_PRESTIGE_CAP=10`（书目 prestige_paid 记账，达封顶后读者仍得收益、作者不再得声望）。
- 结算在研读落账点同步完成，以 readers 追加与 prestige_paid 累加为幂等锚：同一读者重复研读不重复结算。原子性口径（评审 M2）：锚（readers/prestige_paid/prestige_pending）先落库成功才给读者入账，落库失败整单回滚可重试；作者声望经 `prestige_pending` 补结——作者落库失败时待结留账，下次研读一并结清，不丢不重；著书建目落库失败全额回滚（灵感/寿元/物品）。`_save` 返回成败并记日志，禁止静默吞异常。
- 作者已陨落/转世（旧 id 不存在）：声望无处落，跳过结算，读者收益不受影响。

### 3.5 流通绑定钩子（双端同口径，经既有寄售指令）
- `/寄售 亲笔手稿 <价>` 成功后：书目 state=listed、记 listing_id（holder 不变仍为卖家）。
- `/买寄售` 买中手稿：买家须未持有手稿（入口校验，持有则拒绝且不成交）；成交后书目 holder=买家、state=held、清 listing_id。
- `/撤单` 撤回手稿：书目 state=held、清 listing_id。
- 交谈赠予手稿成功：书目 state=gifted、holder=NPC（终态，不再流通/不可读）。

### 3.6 指令与口径
- `/著书`（面板：灵感进度/可写状态/在持书目/声望）、`/著书 写`、`/研读 [参]`；英文别名 `/write_book`、`/read_book`。server 与 cli 同引擎同文案。
- 死亡：著书/研读均拒绝（引擎双查 status 与寿元）。
- 闭关：双端均不入闭关白名单——著书与研读一并锁门（与 F02/F06/F10 防临场口径一致；无既有研读口径可对齐，故从严同著书）。
- 网页：修行卡加「著书」「著书·写」「研读」按钮（data-cmd 模式），app.js 补 hint；`_status_dict` 纯新增 `books: {inspiration, prestige}`。

## 四、边界

- 寿元恰在边界（剩余 == 成本+保留线）→ 拒绝（须严格大于）。
- 灵感恰 10 → 可写，写后归 0。
- 读者已在 readers 中、作者本人、书目 state 非 held（寄售中/已赠）→ 均不可结算收益。
- 书目行缺失但行囊有手稿（历史逃逸）→ 研读 fail-closed 提示「此稿来历不明，无字天书」，零收益。
- 行囊无手稿但有 held 书目（逃逸）→ 同样 fail-closed。
- NPC 角色不使用指令；NPC 持有（gifted）为终态不回流。
- 旧档：Character 无新字段 JSON 可反序列化（默认 0）；无 books 表时 init_db 自动建（IF NOT EXISTS）。

## 五、Out of Scope

- 书入商会官价目录/系统回收、典当、拍卖、当面交易、宗门上交（明确拒绝，非未做）。
- 合著/续写/书评、按本收费分成（寄售价归卖家既有通道，与作者无关）、声望排行榜与声望消费点（声望字段先落账展示，后续功能自取）。
- NPC 著书、NPC 研读玩家之书。
- 多本持有与书架系统（实例 id 化改造属架构变更，另立项）。
