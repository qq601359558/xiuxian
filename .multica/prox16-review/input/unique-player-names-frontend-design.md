## 2. 五步需求细化与真正需求

1. **解构本质**：不是给 409 换颜色，而是让玩家知道哪一步没有完成、如何修改，并信任失败不会偷换角色或消费道统。注册、显式转世两处应解释同一个道号规则。
2. **可行性**：原生 JS 的共享错误映射、现有表单提交态和消息流足够；映射为固定表，不加查重接口、不引库。服务端负责 Unicode 比较和原子性，前端不用另造权威校验器。
3. **盲区**：HTTP 失败与 HTTP 成功内 `ok:false` 必须一起覆盖；原始长度截断、重复 Enter、探测覆盖错误、旧响应跨登录模式、只有 `error` 无 `text`、非洞府页面看不到消息、自动重试与隐式续玩均可能造成误导。
4. **举一反三**：登录与 `/join` 的缺角色也应复用映射；以后新增错误码只扩一处。未知错误仍走旧兜底，不把认证、账号重名、网络或服务故障统统映射成道号冲突，不扩展成玩家改名系统。
5. **完善方案**：统一基础文案与场景包装，注册在原表单纠错，显式转世失败保留死亡态与指令；缺角色给出现有登录/注册按钮可执行的下一步。提交锁、焦点、朗读、未知结果均有确定规则，交阶段三确认后实施。

### 真正需求 / 行为契约

- **问题**：注册失败可能丢错误码，转世失败可能不显示且清空输入，玩家无法判断是否已经入世/转世。
- **行为**：三种已知错误码按下节唯一文案表呈现；注册不跳页、不清空输入；显式转世失败不暗示成功、不变更角色/道统/会话；缺角色绝不自动创建角色。
- **边界**：后端归一与最终校验为准；裸 `/转世`、已死角色登录/续玩保持沿旧名的既有契约；失败与网络结果不明不能混为一谈。
- **验收**：下列 A1–A8 均可独立走查；用网络记录核对 HTTP/code，用 UI 观察保留/恢复/朗读；状态原子性由服务端 QA 在隔离库独立验证。
- **明确不做**：本轮不编码、不运行服务、不读取真实存档、不执行迁移；不加组件、样式、token、框架或依赖；不设计自助改名、NPC UI、管理员工具或新联系页面。

补充裁定：

- 上述转世包装只用于服务端明确返回的 `NAME_TAKEN/INVALID_NAME` 且本次是显式 `/转世 新道号` 或既有等价 `/reborn 新道号`；不把所有失败都描述为「死亡态、未消费」。
- `CHARACTER_MISSING` 不是正常转世的预定返回，不编造这个组合的成功/重建规则；若行动端意外收到此码，使用同一缺角色引导回门庭，不显示「转世未成且仍死亡」。
- 注册账户重名保持原有账号错误，不提示改道号。`AUTH_FAILED/AUTH_REQUIRED` 保持既有认证引导；未知码按 `error → text → message → 既有通用失败文案` 回退，并以纯文本/现有转义显示。
- HTTP 映射：注册撞名 409、非法道号 400；登录及 `/join` 缺角色 409；action 沿原传输约定按 `ok:false` 判断业务失败，不能要求所有业务失败变成 HTTP 409。
- 未收到可信业务响应时不使用任何「未消费」「仍死亡」断言。注册网络异常提示「未能确认注册结果，请检查宗门阵枢；若提交后连接中断，请先尝试登录确认，再决定是否重试。」；显式转世网络异常提示「未能确认转世结果，请检查连接并核实角色状态后再决定是否重试。」。均保留输入、不自动重发或触发登录/续玩。

## 4. 注册、登录与修改重提流程

### 注册状态机

`初入仙途 → 填写 → 提交中 → 明确失败 → 修改 → 再提交 → 服务端成功后入世`

1. 注册模式复用现有 `fNameWrap`。只调整现有标签文案为「本命道号（可留空沿用账号；归一后 2–12 字）」，不加提示块、计数器或气泡。账号和密匙仍用既有必填规则。
2. **不提供实时查重、不弹「将按归一处理」通知、不预先宣称可用**。标签说明长度，最终失败文案解释规则。前端不自动改大小写、不把比较键回填、不做繁简转换；界面原输入一直保留。
3. 道号完全未填时允许沿用账号作为候选；非空但全是空白必须作为显式非法候选交给服务端，不能 `.trim()` 后回退账号。去掉道号原始 `maxlength=12`，粘贴 13 字不得变成另一个 12 字名字；最终字数以服务端 NFKC、Unicode 空白折叠/去首尾后的长度为准，不用 JS UTF-16 `.length` 作权威判断。
4. 进入提交前先查现有提交锁，重复事件直接忽略，不能先清掉正在显示的消息。开始新请求时清空上一轮 `gateMsg` 和无效关联，再禁用现有提交按钮并显示原有「灵脉感应中…」。
5. 同一提交态临时锁住现有模式切换、探测、离线演示按钮；四个输入只读但不清空。取请求快照并保持同一模式/阵枢，避免返回后提示对应另一个账号或登录标签。请求结束恢复各控件原状态，不引入定时冷却或组件。
6. 已知失败只写 `gateMsg`，不再另发门庭错误 toast；恢复按钮原文与可操作态，再按表回填焦点。失败不写入新 token/name/uid，不隐藏门庭、不预先绘制角色。
7. 用户修改相关道号字段时清掉该轮道号错误与 `aria-invalid`；连续失败每轮先清空、后写入最新结果，同文也重新通知。切换登录/注册清掉不适用错误、恢复原标签逻辑，但不清输入；不自动提交。
8. 只有服务端确认成功才沿既有路径入世。成功使用服务端返回的显示名；既有成功流程不扩展为客户端改名。没有按时间限制重试，失败返回即可修改并重提。

### 缺角色的可执行恢复路径

- `/login` 或 `/join` 返回 `CHARACTER_MISSING` 时留在/返回登录门庭，显示表中的完整引导；不签入工作台、不发送建号/转世请求，也不采用 `fName` 代替角色。
- 保住现有账号的路径是联系**当前部署站点的管理员**恢复角色；当前 UI 没有管理员联系方式，不虚构邮箱、帮助中心或新增按钮，也不承诺恢复时间。
- 想立即重新开始的路径是点击现有「初入仙途」，**手动填写不同仙籍账号**后注册。原账号已存在，使用同账号再次注册不是可行恢复方案；文案不承诺带回旧角色或旧道统。
- 正常已有角色登录忽略客户端道号；已死角色续玩沿存档旧名。显式转世失败后不自动调用 login/join 试图「修复」，避免触发既有已死续玩下一世行为。

## 5. 显式转世失败流程

`已有死亡角色 → 输入 /转世 新道号 → 既有 busy 锁 → 明确失败 → 原角色保持 → 改指令重提`

1. 复用 `checkActionLock/busy`，提交中按钮和重复 Enter 都不得发第二条请求；不额外加 debounce 库或人为等待时间。指令行不提前清空，后续用户若已编辑，不用旧响应覆盖新草稿。
2. action 返回 HTTP 成功且 `ok:false` 时也读取 `code/error/text`。两类已知道号失败先经过共享映射，再 `pushFeed` **一条**失败消息；不能因同时有 `error` 和 `text` 写出两条，不重复显示默认「敕令失败」。
3. 现有持久消息只在玄阁洞府可见。为保证任何主境提交都能找到错误，**仅这两类显式转世失败**将前端视图切到现有「玄阁洞府」，滚至「仙途行止 · 因果纪事」，保留底部敕令输入；这只是 `setView` 的 UI 导航，不是迁跃，不发新 API、不触发登录/续玩。已在洞府不重复切换；其他指令保持现有行为。
4. 消息使用现有条目模板；该条原有「因果显现」标签换文案为「转世未成」，正文用表内完整句，沿用现有文字/背景样式，不依赖红色识别失败。最新条在原来的最前位置，不扩展历史容量或新增全局日志。
5. 只在收到服务端明确失败时陈述死亡态/未消费。失败不乐观置为存活、不改道号、不扣道统、不替换 token，不刷新来触发新一世。若失败响应附带状态，只接受符合既有代际/版本规则的服务端权威快照，不自行构造失败后角色。
6. 请求结束解除 busy；两类已知失败保留本次指令（或用户已编辑的新草稿）、隐藏旧建议并保持可编辑。成功以及其他指令的清空策略不变。完整 `/转世 新道号` 留在输入中供改字，不新增「重试」按钮。
7. 只保持既有 `/转世` 和 `/reborn` 等价入口，不做模糊前缀匹配。**裸 `/转世` 无新名参数**沿用旧名，不因前端长度规则变成 `INVALID_NAME`，也不弹新名输入窗口。

### 朗读与键盘规则

- 门庭用**一个**既有 `gateMsg role=alert` 通知结果；同码连续失败通过「本轮清空 → 新结果写入」再次通知。提交中不往 alert 塞进度文案，不同时发错误 toast，不将焦点跳到无交互错误块。
- 道号错误返回后恢复 `fName` 焦点，关联错误并保留输入；缺角色只回 `fUser`，不错误标记用户名格式。控件恢复后 Tab 可达现有模式按钮，Shift+Tab 可逆；无焦点陷阱，不强制全选删除。
- 行动失败既有 toast 与持久消息使用同一完整文案；toast 的现有 `aria-live=polite` 是**唯一自动朗读通道**。消息区设可访问名称供屏幕阅读器导航，不再加第二个 live region，防 `renderBody` 重建最近 4 条时整段历史重复播报；不把聊天区 `chatLog` 误作行动流。
- 敕令仍在底部原输入；键盘提交本来就在输入内时不额外重聚焦，鼠标提交后可返回输入。滚动消息区不夺取键盘焦点；不把整条错误再绑给输入并触发双重朗读。
- 失败以「未成」正文/标签而非单独颜色表达。360px 与桌面、200% 缩放均应显示全文并可滚达恢复按钮；长登录提示不得裁切。现有 gate 固定定位在矮视口可能出现滚动问题，列入走查，若确证须另提最小滚动规则回评审，不在本轮静默加 CSS。
- 不加动效；切主境/滚动服从 `prefers-reduced-motion`，减少动态偏好用即时滚动。沿用当前 light/dark 机制，不宣称现有主题对比度已合格；验收检查实际背景下正文 ≥4.5:1、焦点可见。
